## Design

- **Shared screen, no output messages.** The screen is one `Uint8Array` over a
  `SharedArrayBuffer`: char and attribute per cell, row by row, then cursor column and row
  (`host/terminal.js` documents the layout; attribute = fg bits 0-3, bg bits 4-6, blink bit 7).
  The program Worker writes it, the page repaints it every animation frame, and a frame that
  equals the previous one (same blink phase) is not painted. Chosen over posting draw ops
  because there is no message flood, no ordering problem, and a stopped program leaves its
  last screen behind. Torn frames are possible in principle (the page copies the 4 KB while
  the program writes) and are repaired by the next frame.
- **Key queue.** `host/keys.js`: Int32 ring (64 slots) in a SAB, HEAD owned by the consumer,
  TAIL by the page. `readKey` is `Atomics.wait` on TAIL, `keyPressed` a peek. `pushKeys` is
  all-or-nothing so an extended key (0 then scan code) is never split. `keyBytes` maps a
  keydown event to ReadKey bytes (Enter/Backspace/Tab/Escape, Ctrl+letter, arrows, Home/End,
  PgUp/PgDn, Ins/Del, F1-F10, CP437 characters above ASCII via the glyph table).
- **sleep** is `Atomics.wait(pause, 0, 0, ms)` on a private never-notified word.
- **Stop** is `Worker.terminate()`; it ends a program blocked in `readkey`, in `sleep` or in a
  loop that never calls the host (all three tested/smoke-tested).
- **Teletype.** Programs without Crt use `write` (fd 1/2); `teletype(cells)` in `worker.js`
  puts the bytes on the shared screen (CR, LF, BS, BEL ignored, wrap, scroll). Its cursor lives
  in the screen bytes so no other state exists.
- The Worker adds `readkey`, `keypressed`, `sleep` to `host.imports` after constructing `Host`;
  `runtime.js` is untouched. `ReadLn` in the browser is not covered (empty console input).

## Assumptions for #60 (Crt, grid model, `screen` import)

- `host/screen.js`'s grid model must keep its cells in the shared layout above (give it the
  `grid` view the Worker receives instead of allocating its own arrays), including the cursor
  bytes; the `screen` import then needs no transport. If #60's model keeps its own arrays, it
  must copy into the layout, or the layout in `terminal.js` should be revised on integration.
- `Delay` calls host import `sleep(ms)` (decision 38): `worker.js` provides it with real
  waiting; the clock stays real (`nowMs`), so decision 38's virtual clock is not needed here.
- When #60 lands, `teletype` should be replaced by the model's own console print if it has
  one (it would then duplicate it), and the `Object.assign(host.imports, ...)` in
  `runProgram` becomes constructor arguments of `Host`.

## Files

- `host/terminal.js` (70 counted lines): layout constants, `CP437` (256 glyphs, three data
  rows), `PALETTE`, `clearScreen`, `Terminal` (`draw(nowMs)`, `start()`), blink at 500 ms,
  cursor as a 2 px bar in the cell's foreground colour.
- `host/keys.js` (41): queue and key mapping.
- `host/worker.js` (59): `runProgram`, `teletype`, the browser `onmessage` entry (only when
  `WorkerGlobalScope` exists, so Node tests import the module).
- `host/main.js` (33): page wiring (`?wasm=URL`, Run, Stop, keydown).
- `host/index.html` (no logic, not counted), `tools/serve.mjs` (16 lines, COOP/COEP,
  path-traversal guard), `README.md` (header section).
- Tests: `tests/host/{keys,terminal,worker}.mjs` with `browser_helpers.mjs` (hand-built wasm
  programs importing the interactive host functions: echo/sleep/peek, spin, empty) and
  `node_worker.mjs` (worker_threads stand-in for the browser entry); run by
  `compiler/tests/host_browser.rs`. They check: FIFO and wrap-around of the ring, peek not
  consuming, full queue refusing and all-or-nothing extended keys, readkey blocking in a real
  thread until a key arrives, key mapping (positive and negative: modifiers, F11/F12, non-CP437),
  glyph table, colours, blink, cursor, redraw only on change, program echo/sleep >= 40 ms/peek,
  readkey blocked with no output, exit status, bad module error, terminate while blocked and
  while spinning (main thread keeps ticking), teletype cases (CR/LF/BS/BEL, wrap, scroll).
  No Pascal output is compared, so there is no TP 5.0 oracle expectation in these tests.
