# #54 Text files

Branch `54-text-files`.

## Stage 1: RED

### TP 5.0 findings (probes in `tmp/pr`, every program run with `tools/tp5.sh`)

The I/O error rules of #49 are refined. With `{$I-}` and an error pending (`InOutRes <> 0`):

| Call | Effect while an error is pending |
|---|---|
| `Assign` | runs; never fails; `{$I+}` does not raise the pending error at an `Assign` (program ends with exit 0) |
| `Reset`, `Rewrite`, `Append`, `Close` | **run** (a `Reset` of a good file rewinds it, a `Rewrite` creates the file, `Close` closes it). A failure of theirs **replaces** the pending code (`Close` of an unopened file after a failed `Reset` gives 103); a success leaves it unchanged |
| `Read`, `ReadLn` | skipped, but the items are assigned: Integer 0, Real 0.0, String '', Char `#26`; the file does not move |
| `Write`, `WriteLn` | skipped (console included, as #49 found) |
| `Eof`, `Eoln` | skipped, both return False |

A skipped call does not replace the pending code (a `Read` of a closed file after a pending 2 leaves 2). Under `{$I+}` the
raise comes after the statement: a pending error is raised by the next I/O statement (`{$I+}` then `WriteLn('x')` prints
nothing and ends with runtime error 2). The check is not made after `Assign`.

Other findings, each pinned by a fixture:

- A line ends at CR (then an optional LF). A LF alone is an ordinary character (`LFONLY.TXT` read by `ReadLn` is one 14-byte
  line); a lone CR ends a line (`a CR b CR CR c` is `a`, `b`, ``, `c`). After `Read(c)` returned the CR, `ReadLn` skips up
  to and over the **next** CR LF (it eats a whole following line), so a runtime must not "see" that the CR was already consumed.
- `Read` of a number into Byte/ShortInt/Word/Integer keeps the low bits (300 to Byte is 44, -129 to ShortInt 127, -1 to Word 65535,
  99999 to Integer -31073). A number beyond LongInt, or followed by letters (`34x`), is 106. `Eof` of an output file is 104.
- Console `Read` of numbers skips blanks and blank lines; at the end of the input it gives 0.
- A Text variable is not a record: `f.Mode` is 121, `f = g` is 41, `f := g` and `Input := f` are 43, `Eof(n)` and `Reset(s)` are 77,
  `function F: Text` is 34, `Reset(f, 1)`, `Eoln(f, g)`, `Read(f, n:3)` and `ReadLn(f, n + 1)` are 89, `Assign(f)` is 87,
  `Read` of a pointer, enumeration, array or Char array is 64 (a Char array cannot be read), `Close(5)` and `ReadLn(f, 5)` are 20.
- `Text` is a name like any other: it can be aliased (`type TFile = Text`), put in records and arrays, and used as a `var` parameter
  bound to `Output` or to a file.

### Design (for the lead; the tests do not depend on the parts marked *free*)

**System (`runtime/system.pas`).** `type Text = record Handle: LongInt; Mode, Pos, Len: Integer; Ended: Boolean;
Name: String[79]; Buffer: array[0..255] of Char end`. `Mode` is 0 unassigned, 1 closed, 2 input, 3 output, 4 console
input, 5 console output. `Input` and `Output` are typed constants of type Text that name only the leading fields (the typed-constant
initialiser accepts the first fields, rest zero), so they need no start-up code. Their image is the whole record (about 350
bytes of data) but is emitted only for a program that names them or reads the console: an implicit console **write** passes the
file address 0, which `TextOut` takes for the console, so hello-world carries neither constant. `InOutRes` is a System variable. The five host
calls are `external` declarations (`fs_open`, `fs_read`, `fs_write`, `fs_close`, `readline`, decision 29). Routines: `TextOut(file,
address, count)` (`file` an address, 0 for the console) (replaces the direct `HostWrite` calls of the compiler's `write_string`/`write_integer`/Real/newline code: console
mode calls `HostWrite`, file mode `fs_write`, pending error or wrong mode do nothing or set 105), `CheckIo` (raises
`RunError(InOutRes)` after clearing it), `IOResult`, `Assign`, `Reset`, `Rewrite`, `Append`, `Close`, `Eof`, `Eoln`, and the Read
helpers `ReadChar`, `ReadLong`, `ReadReal`, `ReadStr` (each `var f: Text`, result by function; `ReadStr` takes the capacity) and
`ReadLnEnd`. One buffer fill routine serves files (`fs_read`, a ^Z ends the data) and the console (`readline`, then the runtime
appends CR LF, decision 32). Numbers are collected as text and converted by `ValLong`/`ValReal` (`docs/prs/43.md`), failure is 106.
Append of a missing file is the host's -2 (decision 32), so System calls `fs_open` mode 2 and no longer creates.

**Compiler.** Checker (about 100 lines): (1) `Write`/`WriteLn`/`Read`/`ReadLn`: when the first argument is a Text variable it is the
file, else the file is absent (a write goes to address 0; a read gets a `Var` node for `Input` in front);
(2) `Read` is rewritten into a compound of `v := ReadX(f)` assignments (`ReadStr(f, capacity)` for strings, narrowing is the ordinary
assignment), then `ReadLnEnd(f)` for `ReadLn`; other types are 64, a field width is 89; (3) `Eof`/`Eoln` without argument use `Input`;
(4) 77 for a non-Text argument of a Text `var` parameter, 126 for a Text value parameter, 43 for assignment, 41 for comparison,
34 for a Text result, 121 for a field of a Text. Types/symbols: `Text`, `Input`, `Output` and the Read helpers bound by name after
System loads (like `HeapOrg`). Parser/lexer/directives: `{$I+}`/`{$I-}` in the token-carried switch state of #53 (a bit next to
`range_checks`, local to a source file, stamped on nodes). Codegen: `write_string`/`write_integer` take the file address and call
`TextOut`; after a call of a checking routine (a routine whose first parameter is a Text, except `Assign`), after a `Write`, and after
each `ReadX`, `call CheckIo` when the node's I/O bit is set; the check is therefore a compile-time property of the call site
(`the_switch_decides_at_compile_time...` pins it).

**Budget estimate (this issue).** Checker +100 (allowance 1.5x = 150 of the ~413 left), codegen +40, parser/lexer/directives +20,
types/symbols +30, System +250 (374 to about 625 of 1,500). No host change.

### Consequences the lead should know

1. Every program that writes imports `host.fs_write` (and `rterror` as before), because `TextOut` dispatches on the file mode at
   run time. Tests that instantiate compiled modules with a hand-written host (`host_imports.rs`, `frames.rs`, `nested.rs`,
   `wasm_*.mjs`) will need `fs_write` in their import objects: a mechanical test change I will list in GREEN for approval.
   A program that never reads or opens a file imports neither `readline`, `fs_open`, `fs_read` nor `fs_close`
   (`a_program_that_only_writes_needs_no_input_or_open_and_close_calls`).
2. Console input lines are limited by the buffer: `readline` is called with `max` 254 and a longer line is cut (ABI: the rest is
   discarded). TP reads a redirected line of any length. Deviation to record in `docs/deviations.md` at GREEN (no test pins the cut).
3. `Text` is a record in our System, so its field names would be visible. The checker rule 121 hides them (pinned by
   `text_file_has_no_fields`). `SizeOf(Text)` is about 350, not TP's 256.
4. `tests/host/vfs.mjs` changes for decision 32 (below); `tests/vfs.mjs` and `docs/abi.md` follow in GREEN.
5. `{$I-}` inside a unit or include file follows #53's rule (file-local; an include's switch stays after it, pinned by
   `io_switch_in_an_include_stays_after_it`).
6. The brief mentions Dos programs in PENDING (`dos_*`, 3 lang, 1 neg); they are not targets here (Phase 6).
