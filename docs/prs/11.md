# #11 LOC counter and budget gate

Branch: `11-loc-counter-and-budget-gate`.

## RED stage

### Interface the tests pin

- `tools/loc.sh [ROOT [BUDGET]]`. Defaults: `ROOT` = repo root (derived from the script
  location, not the cwd), `BUDGET` = `tools/budget.txt`. Budget paths are relative to `ROOT`.
- Budget file: one entry per line, `name|limit|paths`. `paths` are space-separated files or
  directories (directories searched recursively). Blank lines and lines starting with `#`
  are ignored. The last entry is `TOTAL|limit`. Language is chosen by extension: `.rs`,
  `.pas` (also `.pp`, `.inc` allowed), `.js`; other files in a counted directory are ignored.
  Paths that do not exist count 0 (the real budget names files that later issues create).
- Output, one line per component then the total: `<name>: <count> / <limit>` and
  `total: <count> / <limit>`. Each over-limit entry additionally prints `OVER: <name>`
  (`OVER: total` for the total). Exit 1 if any `OVER` line was printed, else 0. A run with
  nothing over prints no text containing `OVER`.
- Counting: non-blank, non-comment-only lines. A line with code before or after a comment
  counts. Comment openers inside string or character literals are code. Pascal `{$...}`
  directives count as code. Pascal has no `//` comment (not tested).
- Rust formatting (decision): loc.sh counts a rustfmt'd temporary copy
  (`--edition 2021 --config max_width=100`); the source file is never modified. Counting
  therefore cannot be changed by layout. Fixtures `counts/rs/*`, `literals/l.rs` are
  rustfmt-clean (checked by a test) so their expected numbers do not depend on rustfmt
  behaviour; `fmt/unformatted.rs` is the case where formatting changes the count.
- Total limit: 15,000 as the brief and CLAUDE.md state. `plan.md` §1's table sums to 14,500
  (the 500 margin is the slack). `budget.txt` carries component limits summing to 14,500 and
  `TOTAL|15000`.

## GREEN

### Changes

- `tools/loc.sh`: python3 (`-I`, stdlib only) script. A character state machine over each
  file tracks comment and string state across lines; a line counts when it holds a
  non-space character outside comments (string contents and `{$...}` directives are code).
  Rust: nested `/* */`, raw strings with `#` fences, escapes, char literals versus
  lifetimes (a quote followed by `\` or a closing quote two characters on is a char
  literal). Pascal: `{ }`, `(* *)`, `'` strings with doubled-quote escape. JS: `//`,
  `/* */`, `'` `"` and backtick strings (no `${}` nesting, no regex literals). Rust files
  are piped through `rustfmt --edition 2021 --config max_width=100 --emit stdout`; the
  source is untouched and a rustfmt failure aborts with a message.
- `tools/budget.txt`: plan §1 components, limits sum 14,500, `TOTAL|15000`.
- `Makefile`: `test` also runs `sh tests/tools/loc_test.sh`; `check` is fmt, clippy,
  `make test`, `tools/loc.sh`; new `loc`; new `hooks` installs `scripts/pre-commit` into
  `git rev-parse --git-path hooks` (the shared hooks directory).
- `scripts/pre-commit`: `exec make check`.

### Commands

  0 failed, `tools/loc.sh` exit 0.
- `make hooks`: not run (it writes to the shared git hooks directory, which affects all

### Decisions

- Implemented in python3 rather than sh/awk (review point 3); about 120 lines with the
  docstring, a state machine rather than a pipeline because strings, nested comments and
  raw strings need cross-line state.
- Known limits: JS regex literals and template `${}` expressions, Pascal `//`.
