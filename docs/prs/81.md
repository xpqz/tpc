# #81 Argument error numbers for nil and for parameterless calls

Branch: `81-argument-error-numbers-for-nil-and-for-parameterless-calls`.

## Rules found with `tools/tp5.sh`

1. TP type-checks the arguments that have a parameter before it counts them. A wrong
   argument type (26, or 20 for a non-variable to a `var` parameter) wins over "too few"
   (87) and "too many" (89), for user, unit and System routines.
   `Compile('P.PAS', nil, R)`: TP 26, we gave 87.
2. A parameterless routine called with arguments: TP reads the call as complete and fails
   on the `(` with whatever the enclosing construct expects next. The origin of the
   routine (user, unit, System) does not matter. In an assignment right-hand side or
   operand it is 85; inside the argument list of another call (`WriteLn(Run(1))`) it is 89.
   We chose by origin: User gave 89 everywhere, Unit and System 85 everywhere.
   Other contexts give other numbers in TP (`if Q(1) = 1` 40, `a[Q(1)]` 93, `for i := Q(1)`
   58, `case Q(1)` 54); not reproduced, they stay 85 here.

## Change (compiler/src/check.rs)

- `arguments` checks the paired arguments first and reports the count error last.
- `call_depth` counts enclosing calls (`within_call` wraps statement and expression
  calls); a parameterless call at depth above 1 inside an expression is 89, else 85.
  `argument_count_error` no longer takes the origin.
