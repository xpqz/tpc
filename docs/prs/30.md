## Method

nothing is hand-written, fpc was not used. Probes lived in `tmp/p30/` (git-ignored).

TP5 findings beyond docs/prs/27.md (all probed):

- Calling through a variable: only a variable of *procedure* type is a statement. A function
  variable as a statement (`f(1)` or `g`) is 91 `:=` expected, like any other variable. A
  procedure variable with arguments it does not take is 85 (`p(1)`), too few arguments 87, a
  constant for a `var` parameter 20.
- Bare identifiers in expressions: a procedural *function* variable is called (`g + g`,
  `WriteLn(g)`, `if g = 1`); one that needs parameters is 88; a procedure variable is 143
  (`WriteLn(p)`).
- When a procedural variable or parameter receives a value, the right side must be a routine name
  or a procedural variable: a variable of another type or signature is 26 (`p := n`,
  `p := f` with `f` a function variable); a literal, a named constant or `@Name` is 20;
  `Use(3)` is 20.
- `for p := ...` with a procedural variable is 97.
- Type section: `type A = Integer` makes an identical type (a `var` parameter of type `Num`
  accepts an `Integer` variable and rejects a `Byte` one, 26); duplicate name 4; a type used
  before its declaration 3; `type T = T` is 21; unknown parameter or result type 3; missing result
  type or parameter type in a procedural type 86; missing `;` 85, name 2, `=` 90.
- `{$F+}` is switched at the routine's header; `{$F-}` or no directive rejects the assignment
  with 143 (`routine_assigned_without_far_directive`, the deviation below).

## Intended behaviour (design the tests assume)

- Parser: `TYPE` section with `Name = spec;` where the spec is a type name or `procedure
  [(params)]` / `function [(params)]: Name`; a procedural type written in a `var` declaration is
  desugared to a hidden type declaration. Directive tokens: `F+`/`F-` (any case) are ignored,
  any other directive is 200 until the directives phase. `@x` parses; the checker gives 20 where a
  procedural value is expected and 200 elsewhere.
- Types: `Type::Proc { params: (Ty, byref) list, result }`, interned by content, so type identity is
  structural compatibility and an alias is the same `Ty`. A procedural value is 4 bytes and is
  loaded and stored as an unsigned ordinal.
- Checker: a routine name where a procedural type is wanted becomes `ProcRef(routine)` after checks
  in this order: nested routine 143, signature mismatch 26 (also procedure versus function). A
  variable of procedural type is a value there, a call elsewhere (statement: procedure type only;
  expression: function type, 88 with parameters, 143 for a procedure). `Indirect(callee, args)`
  calls through a value, with the argument checks of a direct call. `for` over a procedural
  variable is 97.
- Codegen: one WASM type per signature (`Module::ty` interns); table of `[stub, routines whose
  address is taken, in routine order]`, `ProcRef` is the table index; `call_indirect` after the
  arguments. The stub is a function that executes `unreachable`.
- `{$F+}` is ignored: this compiler accepts the assignment of a global routine with or without it
  (TP5: 143 without). Recorded as D11 in docs/deviations.md in GREEN.
- Expected LOC: parser +45, types +25, checker +90, codegen +40.

## Changes

- `compiler/src/ast.rs`: `TypeDecl`, `ProcType`, `AddrOf`, and the checked kinds `ProcRef` and
  `Indirect`.
- `compiler/src/parse.rs`: `drop_directives` (only `F+`/`F-` allowed, removed from the token
  stream; others are 200 at the directive); `params` factored out of `routine` and shared with
  procedural types; `type_spec`; the `TYPE` section; a procedural type in a `var` declaration
  becomes a hidden `TypeDecl` (name `' '` plus bytes no identifier has); `@` as a prefix.
- `compiler/src/types.rs`: `Type::Proc` interned by `Types::proc`, `Types::sig`; a procedural
  value is a 4-byte unsigned ordinal for `ord`; `Routine::addressed`.
- `compiler/src/check.rs`: `spec` (type declarations, `type T = T` is 21), `signature`,
  `proc_value` (a global routine of the wanted signature becomes `ProcRef`, a variable of that
  type stays a value; nested 143, mismatch 26, other names and expressions 20), `indirect` and
  `routine_params`; `arguments` takes the signature, not the routine; a variable of procedural
  type is a call statement only for procedures (otherwise 91), and a call in an expression for
  functions (88 with parameters, 143 for a procedure); `for` over a procedural variable is 97;
  `@` in an expression is 200.
- `compiler/src/codegen.rs`: `Layout` (literal addresses, WASM type per procedural type, table slot
  per routine); table `[trap stub, addressed routines in routine order]`, always emitted;
  `push_args` shared by `invoke` and `indirect`; `ProcRef` is `i32.const slot`; `Indirect` is
  arguments, callee value, `call_indirect`.
- `docs/abi.md` §5, `docs/deviations.md` D11, `docs/subset.md`, PENDING files (all programs of the
  target lists removed; only the two Real-typed neg programs remain), `compiler/tests/procedural.rs`.

## Two test fixes (provably wrong, RED approved without them noticing)

Both are in `compiler/tests/procedural.rs`, `one_wasm_type_per_signature`, not corpus programs:

1. The `other` source declared a variable `c` and a function `C`; TP5 reports 4 for that
   (checked with `tools/tp5.sh`). The variable is renamed `cb`.
2. The second signature was `function(x: Integer): Boolean`, which has the same WASM shape as
   `Integer -> Integer` (both `(i32) -> i32`), so no new WASM type is correct. It is now
   `function(x, y: Integer): Integer`, and the assertion text says "another WASM shape".

The expectation (one type per shape, a new shape adds one) is unchanged.
