# #84 Compiler panics on indexed assignment to a string function result

Branch: `84-compiler-panics-on-indexed-assignment-to-a-string-function-result`. No RED stop (pre-approved).

LOC before (`tools/loc.sh`): total 10406 / 15000, checker 1972 / 2200. After: total 10433, checker 1999 (+27 checker, codegen unchanged).

## Probed TP 5.0 behaviour (`tools/tp5.sh`)

Inside `function F: string`, `F[i] := c` (constant or variable index, with or without parameters, also from a
nested procedure) assigns an element of the result variable. A read `F[i]` is a recursive call followed by an
index: error 88 `(` expected if `F` has parameters, 121 if it has none. `F[1] := ...` outside `F` is 121,
`F[300] := ...` is 76, `F[1] := 'ab'` and `F[1] := 5` are 26. Indexing a string constant (`Name[1]`,
`'abc'[1]`) is 89. No deviations.

## Change

`compiler/src/check.rs`:
- `assign_statement` calls `resolve_result_indexed` for selector-chain targets: for `Name[i] := v` with `Name` the
  function being defined, the base becomes the result variable (shared with the plain `Name := v` path through
  `result_variable`). Reads are untouched, so they stay calls as in TP5.
- `expr_kind` passes an already resolved `Var` through.
- `index_expr` rejects a base that is not a variable designator before it reaches codegen: 89 for a string
  constant, 121 otherwise. This is what stops the panic for every path, not only this one.
