### How they fail today

expected numbers.

### Oracle findings

- Intrinsic types: `Sqr` and `Abs` use the unary-minus rule (byte-sized and Integer give Integer,
  Word and LongInt give LongInt; `Sqr(Word 65535)` = -131071); `Succ`/`Pred` keep the argument's
  type and wrap (`Succ(Byte 255)` = 0); `Odd` accepts any integer type; `Ord` accepts any ordinal
  (Integer too); `Chr` keeps the low 8 bits.
- Constants may use Abs, Chr, Odd, Ord, Pred, Succ (folded without narrowing: `Succ(255)` = 256,
  `Pred(0)` = -1) but not `Sqr` (133). `Abs(-32768)` as a constant is 32768, while the variable
  form wraps to -32768.
- Argument errors: a call to a parameterless routine does not take parentheses (`Q(1)` is 85 in a
  statement and 89 in an expression); too few arguments 87, none at all 88, too many 89; a type
  mismatch 26; a constant outside the parameter's range 76.
- A forward declaration may be followed by a definition that omits the parameter list (and the
  result type), and the body then sees the forward declaration's parameter names; a mismatch is 131,
  a second `forward` is 36, an unresolved one is 59 reported at the main `begin`.
- Assignment to a function name outside its body is 122, to a procedure name 85; a function
  as a statement is 122, a procedure in an expression 143. Error 4 includes the program name.
- Evaluation order of operands is unspecified in TP: `Show(1) + Show(2) * Show(3)` evaluates the
  right-hand operands first. No test depends on it; arguments of a call and of `Write` are
  evaluated left to right. GREEN adds a `docs/deviations.md` entry.
- TP raises runtime error 202 (stack overflow) near a recursion depth of about 3000; the WASM
  engine's limit is different. Not tested (depth 1000 is the corpus requirement).

### Design for GREEN

- Parameters, locals and the function result are WASM locals of the routine (indexes
  assigned by the checker; temporaries of `for`/`case`/Boolean write follow them). Main-program
  variables stay in static data. Assignments to a local narrow explicitly to its type (a store
  would have truncated). Reading the function name is a call; assigning it writes the result local.
- Routine bodies are wrapped in `block $exit`; `Exit` is `br` to it and the function result is
  read after the block (the epilogue position for later frames).
- Call nodes carry the callee as a `Name` node and are stamped after their last token, where TP
  reports argument errors. Checker-resolved calls become `Invoke(routine, args)`.
- Nested routines, `var` parameters and `String` parameters/results report 200.
- Checks: `Ord`, `Chr`, `Succ`, `Pred`, `Odd`, `Abs`, `Sqr` are intrinsic symbols with their own
  argument rules (38/79).

## GREEN

### Changes

- `ast.rs`: `Op` gains the intrinsics (Ord, Chr, Succ, Pred, Odd, Abs, Sqr are unary operators);
  kinds `Call(callee Name, args)` (statement or expression), `Invoke(routine, args)`, `Exit`,
  `Result`, `Routine`, `Param`, `Block`.
- `types.rs`: `SymKind::Local` and `Routine`, the `Routine` record (parameters and names, result,
  defined, body, locals), and `Types::unary` extended with the intrinsics' result types and
  error numbers (Abs/Sqr 79, Odd/Chr/Succ/Pred/Ord 38).
- `parse.rs`: `routine()` (header with optional parameter list, optional result type, `forward`
  or block), `type_name()` (`String` and `var` parameters report 200), `begin()`, `arguments()`;
  calls are parsed after any identifier followed by `(`, in statements and expressions. Call nodes
  are stamped at the `)` (TP reports argument errors there) or after the name when there are no
  parentheses; the callee keeps its own position. The program node is stamped at the main `begin`
  (error 59).
- `check.rs`: routine declarations with forward handling (4, 36, 86, 131, 59), parameters and
  locals as `Local` symbols, nested routines 200, function result assignment (`Result`), calls
  (`arguments()`: 85/87/88/89, 26, 76; 122, 143), the intrinsics through one `unary()` that also
  folds constants (not `Sqr`), `Exit`.
- `codegen.rs`: each routine and the main program go through `body()`: `block $exit` around the
  statements, function result read after it; `get`/`put` for globals (memory), locals and the
  result (explicit narrowing on assignment); `invoke()` narrows each argument to its parameter
  type; `unary()` emits the unary operators and intrinsics; temporaries are per-function locals.
- `docs/deviations.md`: D9 (operand evaluation order), D10 (error order of programs with two
  errors).

### Design decisions

- Parameters, the result and locals are WASM locals; main-program variables stay in static data.
  Nested routines and `var`/`String` parameters report 200 (no frames in Phase 1); the corpus
  needs none of them.
- Reading the function name is a call; assigning it writes the result local (`Kind::Result`).
- Recursion uses the engine's call stack; TP's runtime error 202 is Phase 2 (review ruling).
