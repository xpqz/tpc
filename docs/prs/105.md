### Design the tests pin

Pure ES modules in `vscode/src/` that never import `vscode`; `extension.cjs` passes the `vscode` API
object into `src/extension.mjs` (injection), so the glue stays thin.

| Module | Interface |
|---|---|
| `latin1.mjs` | `encodeLatin1(string)` one byte per UTF-16 unit (above 255 gives `?`), `decodeLatin1(bytes)` |
| `positions.mjs` | `splitLines(text)`, `errorRange(lines, line, col)` gives zero-based `{line,start,end}`; col is the compiler's 1-based byte column (`lex.rs`: `pos - line_start + 1`), identical to the UTF-16 offset because buffers are sent one byte per unit; line 0 gives the first position |
| `sources.mjs` | `selectSources({mainName, diskNames, readDisk, buffers})` gives `Map name -> bytes` of the `.pas`/`.inc` files, unsaved buffers beating disk files |
| `compiler_service.mjs` | `CompilerService(module)`, `CompilerService.fromFile(path)`, `compile(mainName, bytes, files)` gives `{ok, wasm}`, `{ok:false, error:{code,line,col,file,message}}` or `{ok:false, internal}`; fresh instance per compile; `error.file` is the key of `files` as given |
| `report.mjs` | `buildReport(result, mainName, linesOf)` gives `[{file, message: "Error N: text", range}]` |
| `scheduler.mjs` | `debouncer(delayMs, run)` with `schedule(key)` and `cancel(key)` |
| `locate.mjs` | `compilerPath(setting, extensionDir)` |

Planned counted change: `err_message_ptr()` / `err_message_len()` in `compiler/src/ffi.rs`, over a
`diag::text(code)` shared with `render`. Planned non-source change: `host/package.json`
(`{"type":"module"}`), because the VS Code 1.90 extension host (Node 20.9) has no module-syntax
detection and would load `host/compiler.js` as CommonJS.

### Decisions

- A unit cannot be the main file (the compiler reports error 36 for `tp5c Helper.pas`), so a document that
  starts with `unit X;` is checked through the program `program Tp5UnitCheck; uses X; begin end.`
  (`entry.mjs`); the unit's errors land on its own file.
- Only `.pas` documents are compiled; an `.inc` alone is not a program.
- Characters above 255 become `?` (comment in `latin1.mjs`, review point 3).
- Compiler path: `tp5.compilerPath`, else the release wasm via `scripts/cargo-target.sh` (packaging, #108, bundles it).
- `host/compiler.js` is imported by relative path from `vscode/src/`.

### Evidence

- `make check`: pass (fmt, clippy, cargo tests, shell tests, abi imports, 53 vscode tests, loc).
- `node --test --test-concurrency=1 "tests/vscode/*.test.mjs"`: 53 pass, 0 fail, three runs in a row.
- `make test-browser`: passes (host/package.json changes nothing there).
- `host/package.json` is needed: with `--no-experimental-detect-module` the compiler_service tests pass
  with it (7/7) and fail without it (`host/compiler.js is a CommonJS module`, 0/7), which is what the
  VS Code 1.90 extension host (Node 20.9) would do.
- Grammar scanner is not vacuous (review point 4): removing `begin` from the control keywords fails
  "keywords are scoped in any case"; changing the string rule to `'[^']*'` fails "strings use doubled quotes".
- Loading in VS Code (review point 5): not done. `code`, the `bin/code` launcher and `open -a` with
  `--extensionDevelopmentPath` and a `--user-data-dir` under `tmp/` started no window or process in this
  environment (no logs were written). The `.cjs` entry was therefore not exercised by VS Code; it is
  covered by the manifest test and, for `activate`, by the fake-API test. To check by hand:
  `code --extensionDevelopmentPath=$PWD/vscode --user-data-dir=$PWD/tmp/vsc-data <dir with .pas>`.
