### TP5 findings (probed)

- `MaxInt` is the Integer constant 32767 and `MaxLongInt` (it exists in TP 5.0) the LongInt constant 2147483647;
  `MaxInt + 1` is 32768 and `MaxInt * 2` 65534 (folded, as for any constant). Assigning to one is 113.
- `Pi` is a function without parameters: `Pi := 3` is 122, `r := Pi(1)` is 85, `const c = Pi` is 133 (ours: a
  constant, so the last one is accepted; not tested). `Sin`, `Pi` and the others are redeclarable.
- `Exp`, `Sin`, `Cos`, `Ln`, `ArcTan` accept any integer type or a Real, and give 79 for a Char, Boolean or String
  (not 38). One argument: 89 for two, 88 without. As statements 122, as an assignment target 88.
- `Ln(0)` and `Ln(-1)` are runtime error 207; `Exp(1000)` is 205.
- `FillChar(var X; Count: Word; Value)`: any variable (a string, record, element, field, `p^`, a `Word`). `Count` is
  an integer expression (LongInt accepted, constant outside 0..65535 is 76, Real is 38). `Value` is an ordinal:
  Char, Boolean and integers (a constant outside 0..255 is 76; a variable is stored by its low byte); Real, String,
  set, Pointer are 39. A literal or `(a)` or `a[1]+1` as the target is 20 or 87. Arguments: 87, 89, and 88 without.
- `Move(var Source, Dest; Count: Word)` copies with memmove semantics (`Move(a[1], a[2], 6)` shifts correctly).
- Pre-existing deviations this issue touched: `Inc;` and `New;` were 87 here and are 88 in TP5; `Sqrt(2.0);`, `Abs(1);`
  were 113 and are 122.

  with the count masked to a Word. `compiler/src/wasm.rs`: `memory_fill`.
- `runtime/system.pas`: `Pi`, `ExpReal`, `LnReal`, `SinReal`, `CosReal`, `ArcTanReal`, with series and argument
  reduction explained in comments (D37 in `docs/deviations.md`).
- Tests: the synthetic System of `compiler/tests/system_unit.rs` and `fixtures/system/hook/synthetic.sys` gained stubs of
  the five new helpers.

### Design

`FillChar` and `Move` have no Pascal signature (untyped `var` parameters are omitted), so the checker rewrites each to a
node whose addresses are `@x` nodes; codegen needs no type rules. `Exp` and friends reuse the checker's `Sqrt` operand
rule (79) and become ordinary calls of System routines, so codegen did not grow for them.

shell test suites, `tools/loc.sh`). An earlier `make check` failed in `system_unit` (4 tests) because the synthetic System
lacked the new helpers; fixed in the tests only.
