## Method

Every `.out` and `.err` came from `tools/tp5.sh` on the committed `.pas`; nothing is hand-written and fpc
was not used. Probes lived in `tmp/p35/` (git-ignored). Own programs are in
`compiler/tests/fixtures/enums/{lang,neg}` (the shared tests/ directories are left to the corpus); the
in-scope #33 programs are listed in `compiler/tests/enums.rs`.

TP5 findings (probed):
- `Write`/`WriteLn` of an enum value or constant, with or without width: 64.
- `5..1`: 28. `Red..5` (enum lower, integer upper): 26. Variable bound: 133. Unknown bound: 3.
- Enum identifiers share the scope: duplicates in one type, across types, with a variable, with an
  anonymous `var` enum: 4. `()`, `(a, 5)`, `(a, b,)`: 2. Missing `)`: 89.
- Enums are not integers: `c := 1`, `i := Green`, `c + 1`, `c = i`, enum-for-with-Integer, integer bounds,
  integer or other-enum arguments: 26. Case labels of another type, either way: 74. `if c`: 40.
  `Chr(c)`, `Odd(c)`: 38. Assigning to an enum constant: 113. `Succ(v, v)`: 89.
- Constant assigned to a subrange variable outside it: 76 (also after `v := v + 10; ... v := 20`, a
  non-constant store is not checked). `ng := 300` for `-5..5`: 76; char subrange `'A'` for `'a'..'z'`: 76.
- A subrange variable passed to `var x: Byte` is 26 even for `0..255` (distinct type); an enum subrange
  is not integer assignable (26).
- No range checking at run time: `Succ(Blue)` is 3, `Pred(Red)` is -1, a stored `25` in `1..10` prints 25,
  `s := i` stores unchecked. Storage: `1..300` and `-1..200` hold 300/200 (2 bytes), `0..65535` holds
  65535, `-1..40000` holds 40000 (4 bytes), `-129..127` holds -129, `0..200` holds 200 (1 byte
  unsigned), an enum of 257 values holds 256.
- Arithmetic on subranges uses the base type per decisions 5 and 10: `Hi = 200..250` is Byte-based
  (`h + h` 500, `h * h` -3036), `0..60000` is Word-based and wraps (`w + w` 54464).

## Intended behaviour (GREEN)

- Types: enum `(a, b, c)` and subrange `lo..hi` (constant bounds of one ordinal type, named or anonymous
  in `var`), size smallest of 1, 2, 4 holding the values (sign by lower bound), base type for typing is the
  smallest predefined type holding both bounds (decision 5). Enum values are constants of the enum type.
- Operations: Ord, Succ, Pred, comparisons, for, case, assignment and parameter rules as probed above; no
  range checking.
- New TP errors needed in `diag.rs`: 28, 64, 74, 76, 113, 133 (check the table).
- `SizeOf(type name)` is required by the corpus program `subrange_sizes` only; the smallest form
  (a type identifier, constant result) is assumed. Raise with the lead if this is out of scope.

## GREEN

Tests were not changed. Three own lang programs were added (`enum_signed_storage`,
`subrange_signed_storage`, `subrange_mixed_with_word`, outputs from `tools/tp5.sh`) after probing found
that TP stores `(a,b,c)` and `0..100` as signed bytes and types `Ord(enum)` by its range (decision 16).

Changes:
- `ast.rs`, `parse.rs` (+33): `Kind::Enum`; `type_spec` parses `(a, b)` (an identifier error is 2, a missing
  `)` is 89), or a constant expression that is a type name when no `..` follows, else a `Kind::Range`.
  `var` takes an anonymous type unless the type is an identifier followed by `;`; the hidden `TypeDecl`
  mechanism of procedural types is reused. Parse steps that report the four negatives that passed for the
  wrong reason at RED: `enum_empty`, `enum_number_in_list`, `enum_trailing_comma` (2 at the identifier in
  the `Enum` branch of `type_spec`), `enum_missing_close_paren` (89 at `expect_sym` there).
- `types.rs` (+43): `Tag::Enum`, `base` (the enumeration an enum or its subrange belongs to), `compat`
  (family, and the same enumeration), `enumeration`, `subrange`, one `range` constructor that picks
  storage; `unary` wide/`not`, `promote` use the type's own range.
- `check.rs` (+70): enum identifiers become constants of the enum type; `Range` bounds must be constants of
  compatible types (133, 26) with low <= high (28); `assignable`, case labels and arithmetic use `compat`
  (26, 74); any constant outside the destination range is 76; `Write` of an enum is 64; `T(x)` casts an
  ordinal; `SizeOf(type or variable)` folds to a constant; `Ord(enum)` is typed by the enum's range;
  folded constants keep non-integer types.
- `diag.rs`: 28 and 64. `docs/decisions.md`: decision 16. `tests/lang/PENDING`, `tests/neg/PENDING`: the 9
  lang and 15 neg corpus programs removed.
- Codegen unchanged (loads, stores and narrowing already follow the type's size and sign).
