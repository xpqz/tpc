## Changes

- `compiler/src/lex.rs`: `Tk::Error` and `Tok::error(d)`: a token that stands for a scanning
  error (+16 lines).
- `compiler/src/directives.rs`: `expand` is infallible; the first scanning, directive or
  include error ends the stream with an `Error` token and the `Eof`. `switches` reads the whole
  list before it answers: an invalid item is 17 wherever it stands, `N-`/`E-` are ignored,
  `N+`/`E+` are 200 only when nothing in the list is invalid. `missing_include_code`: 14 for a
  name with a directory part, else 15.
- `compiler/src/parse.rs`: `err` reports an `Error` token's own code; `f(x)[i]` parses as
  selectors so the checker rejects it (121). Parser stops at the final `.` as before, so
  trailing text is never reached.
- `compiler/src/units.rs`: infallible `expand`; a parse error in an include file is not
  re-located against the including file's text.
- `compiler/src/diag.rs`, `ide/errors.pas` (outside the brief's list: the IDE table must equal
  the compiler table, `tests/ide/errors_test.mjs`): messages 14 and 122.
- `compiler/tests/lex_util/mod.rs`: match arm for the new token kind.
- `docs/deviations.md` (D38 note, D42 to D45), `docs/swag.md` (after counts).

Design: TP scans one token at a time, so a scanning error exists only for the parser that gets
that far. An `Error` token in the stream reproduces that with one rule in `Parser::err` and no
parser change elsewhere; nothing can consume the token because no grammar rule accepts it.
