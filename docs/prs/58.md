## Summary

The new code is in good shape: error codes are named, there are no opcode literals, most
functions are under 50 lines, and `units`, `directives` and `symbols` open with a doc that
explains their technique. What a newcomer would still trip over:

1. **A four-field `Diag { code, line, col, file }` literal is written out by hand 7 times in
   `directives.rs` and 4 more times elsewhere** (4 lines each after rustfmt), and a `Diag` with
   `code: 0` doubles as a position type.
2. **`Helper` is listed three times** (enum, `ALL`, `name()`, 32 lines each), so adding a helper
   is three edits that must stay in step (T3 of #47 promised one).
3. **Side-channel state**: `Ast::file/range_checks/io_checks` are stamped onto every node from
   whatever token was consumed last; `Gen::file` carries the target of the current `Write` into
   eight `write_*` methods; `Indexes::text_out` is patched after `Indexes::new`. Each is correct
   and each needs a paragraph the code does not have.
4. **Tuple and bool soup survived in the new code**: `console_or_file -> (Id, usize, bool)`,
   `with_field -> (Id, Ty, u32)`, `array_of -> (Ty, i64, i64, Ty)`, `Kind::TypedConst(u32, u32,
   Id)` (the #47 rule was named fields from three on), `push_args(args, params, false)`.
5. **Duplicated small procedures**: "some routine of this region is still undefined" (4 copies),
   "constant initialiser" test (2), "tokens at line 0" (2), "empty compound node" (3), the
   `Invoke` construction next to `helper_call` (2).
6. **Stale or incomplete docs**: the module docs of `ast.rs`, `check.rs`, `codegen.rs`,
   `lex.rs`, `types.rs`, the `system.pas` header (points at `check.rs`), three lines of the
   CLAUDE.md file list.
7. **Pascal runtime**: TP I/O error numbers (102..106), host mode numbers (0/1/2) and fd 1 are
   bare literals.

### Proof of behaviour preservation

- `tmp/corpus.sh` compiles every `.pas` in `tests/lang`, `tests/neg`, `tests/abi`, `tests/rt`
