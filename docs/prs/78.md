# #78 IDE Menu

Branch: 78-ide-menu (worktree `worktrees/78-ide-menu`).

## Stage 1: RED

### Interface the tests fix (unit `Menu`, `ide/menu.pas`)

`uses Crt, View, Keys` inside. The tests use:

- `procedure DrawBar`: writes the menu bar on row 1 (attribute 70) over View's placeholder and
  leaves the Crt cursor where it was. Main calls `Paint; DrawBar` (View needs no change; the
  placeholder is overwritten in the same screen update).
- `function Run(Letter: Char): Integer`: Main calls `Menu.Run(Keys.MenuLetter)` when
  `ReadCommand` returns `CmdMenu`. `#0` (F10) opens the first menu, `F R C O` the matching one,
  any other letter (Alt-E) opens nothing and returns `CmdNone` without reading a key. Run reads
  keys itself; it returns the chosen command or `CmdNone` when cancelled, and has repainted
  (`View.Paint` then `DrawBar`) before it returns.
- `const CmdNew = 7`: defined in Menu because Keys is not mine to edit; the lead may move it to
  Keys (Main uses `Menu.CmdNew` either way). Options needs no code, see below.
- `procedure Show(Menu, Selected: Integer)`: repaints, draws the bar with `Menu` open and its
  pull-down with item `Selected` (index in the item table, 1..7) highlighted, cursor on the item.
  Run calls it after each key. It is public only so that a test can see an open menu: a
  program that blocks in `ReadKey` ends with exit 255 and `cargo test --test lang` reports that as
  a failure.

Decisions fixed by the tests (to be recorded by the lead):

- Bar: ` File  Run  Compile  Options`, titles at columns 2, 8, 13, 22. **No Edit menu**: the plan
  lists no Edit command; Alt-E is accepted by Keys and does nothing here. View's placeholder
  still says `Edit` until it is changed (it is overwritten by DrawBar, so it is harmless).
- Menus: File = New, Open `F3`, Save `F2`, Quit `Alt-X`; Run = Run `Ctrl-F9`; Compile = Compile
  `F9`; Options = `Environment...`. The plan's "Run: Compile, Run" is split across the Run and
  Compile titles that Keys and View already have.
- Options placeholder: the one item sets the status message `No options yet` and returns
  `CmdNone`; so Main needs no Options code and no command code exists for it.
- Pull-down: 20 columns wide, starting one column left of the title, from row 2, no border;
  open title and selected item are `07`, the rest `70`.
- Keys inside a menu: Up/Down move (wrap), Left/Right change menu (wrap, selection resets to the
  first item), Enter chooses, Esc and F10 cancel, the first letter of an item (either case)
  chooses it, every other key (unknown letters, Home, F1, Ins, Alt letters, ...) is ignored.
- Closing or switching repaints the whole screen through View; nothing saves what was covered.
- Table-driven: titles and items are typed constants of records (no procedural values were
  needed: commands are plain codes).

### Tests (`tests/lang/ide_menu_*`, 39 programs; each has `.pas`, `.keys`, `.dirs` = `ide`, `.out`)

Each program is the editor loop (`View.Reset`, text of 5, 24 or 100 numbered 70-column lines,
`Paint; DrawBar; ReadCommand`, `Menu.Run` for `CmdMenu`, the commands returned logged in the
status message) and ends with the screen uncleared. The golden is the screen dump.

- Bar: `bar_is_drawn_over_the_placeholder`.
- Open menus (via `Show`, 24 text lines so the covered text is visible): `f10_opens_the_file_menu`,
  `alt_f/r/c/o_opens_the_..._menu`, `selection_is_highlighted`, `show_last_item_of_the_file_menu`,
  `opening_another_menu_repaints_the_screen`, `opening_the_file_menu_after_options`,
  `narrow_menu_after_the_wide_one_leaves_no_leftovers`, `menu_open_cursor_is_on_the_selected_item`,
  `menu_open_over_scrolled_text` (after two PgDn), `menu_keeps_overwrite_indicator`.
- Cancel/restore: `esc_closes_and_restores_the_screen`, `f10_closes_an_open_menu`,
  `menu_over_scrolled_text`, `menu_closed_restores_the_cursor_cell`,
  `escape_in_a_second_menu`.
- Choosing: `enter_on_new/open/save`, `enter_on_quit_ends_the_editor` (the editor ends without
  Alt-X), `down_wraps_to_new`, `up_wraps_to_quit`, `alt_r_enter_runs`, `alt_c_enter_compiles`,
  `right_twice_then_enter_compiles`, `left_from_file_wraps_to_options`,
  `letters_pick_items_in_the_open_menu` (s, O, N, then x not an item), `two_menus_in_a_row`.
- Options placeholder: `alt_o_enter_shows_a_message`, `alt_o_letter_shows_a_message`,
  `options_message_is_cleared_by_the_next_key`.
- Negative/ignored input: `alt_e_opens_nothing` (the next key `x` is typed into the buffer),
  `unknown_letter_keeps_the_menu_open`, `unknown_extended_keys_in_the_menu_are_ignored`.
- Integration: `shortcuts_are_still_returned_by_keys` (F9, Ctrl-F9, F2, F3),
  `editing_goes_on_after_a_command`.

No language construct is added, so there are no error-number tests; the negative cases are the
ignored inputs above.

draft in place are byte-identical from this compiler (`cargo test --test lang`: 21 passed). I read
the dumps of the open menus, wrap-around, the scrolled case and the Options message against
the intent. The generator is `tmp/gen_menu.sh` (not committed). The draft was removed for this commit.
