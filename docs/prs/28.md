## Intended behaviour (design the tests assume)

- Memory: initial `sp` 1,048,576 (decision 6). Stack limit 64 KB (TP5's maximum `{$M}` stack):
  a frame whose `fp` would be below `1048576 - 65536` raises `host.rterror(202)`. To go into
  docs/abi.md in GREEN. Routines without a frame cannot overflow the shadow stack; infinite
  recursion of frameless routines hits the host's own stack limit (RangeError), unchanged.
- `sp` is global 0, exported as `sp` always.
- Storage (plan §4.3): the checker records `addr_taken` per variable while checking a routine
  (an argument of a `var` parameter that is a local or value parameter). When the routine is fully
  checked, `Local` symbols with `addr_taken` become `Frame(offset)`; offsets are assigned in
  declaration order, sizes by type, no padding, starting at the base (0 now; 4 once #29 puts the
  static link at offset 0). `Routine.frame` is the size; value parameters that move to the
  frame are listed so the prologue copies them (`store` of the WASM param). `captured` (#29) is a
  second flag feeding the same decision.
- `var` parameter: new symbol kind `Ref`, `val` = local index of the i32 address; a read or write
  loads or stores at that address with the node's width and sign; passing it on as a var argument
  is `local.get`. A global argument is its static address; a frame local is `fp + offset`.
- Prologue (routines with `frame > 0`): `fp = sp - frame; if fp < limit then rterror(202);
  sp = fp`; then param copies. Epilogue after `block $exit`: `sp = fp + frame`, so `Exit` runs it.
- Argument checking follows the probe table: `arguments` takes the parameter's by-reference flag;
  signatures compare it (131 for a mismatch with the forward); `for` rejects a `Ref` control
  variable with 97 (the checker has no 97 yet).
- Bytes of LOC expected: checker about +90, codegen about +70, types +10.

## Open points for the lead

1. `compiler/tests/routines.rs` `UNSUPPORTED` still lists `var_parameter` and
   `var_parameter_in_function` as error 200. This issue removes that error by design; those two
   entries must be deleted in GREEN (the same programs are in `frames.rs` `ACCEPTED`). Not changed
   in RED; needs the lead's approval.
2. Untyped `var` parameters are accepted by TP5 and are not in `docs/subset.md`. The tests expect
   200 (omitted feature). Say if they should be supported instead.
3. The compiler does not read `{$M}` (directives are tokens the parser rejects), so the 202
   programs are compiled without it; only the oracle test inserts it.
4. The `.out` of `frame_for_control_variable_in_memory` prints the control variable after a
   `downto` loop that ended normally (0); TP5 leaves the last value, as our codegen does.
