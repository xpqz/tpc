# #66 Intermittent failure in units corpus test

Branch: 66-intermittent-failure-in-units-corpus-test. Files: `compiler/tests/` only.

## Cause

The brief's suspect (a directory shared by all tests via `work()` / `scratch("x").parent()`)
is not the cause: `driver::scratch` already created `tmp/driver/PID-COUNTER` per call with an
atomic counter, so parallel tests in one process never shared a directory. 20 runs of the
units binary with `--test-threads=16` passed before any change (no reproduction).

What was wrong: the directory is made with `create_dir_all`, which accepts an existing
directory, and nothing ever removes `tmp/driver/*`. Directory names are `PID-COUNTER`, process
ids are reused, and the counter order depends on thread scheduling, so a later process can be
handed a directory an earlier process (possibly running a different test) filled. The corpus
drivers (`check_lang`, `check_rt`, `check_neg`) sweep every `*.pas` in the directory, so one
leftover program without an expectation, or with a different one, fails
`corpus_abi_programs_match_tp5_output`. It needs a pid collision, hence once in many runs and
never alone. This is inferred from the code and a deterministic reproduction of the
mechanism; the original failing run was not preserved.

Other helpers had the same weakness in a different form: `runner.rs`, `runner_files.rs`,
`runner_crt.rs` and the `tmp_dir()`/`wasm_dir()` helpers of eight binaries wrote fixed file
names into a fixed directory (`tmp/runner`, `tmp/integers`, ...), shared by every test of the
binary and by every run.

## RED

`compiler/tests/scratch.rs`:
- `scratch_never_reuses_a_directory_left_by_an_earlier_process`: plants `tmp/driver/PID-N`
  with a `stale.pas` for N in 0..5000 (what an earlier process with the same pid leaves), then
  asks `scratch` for a directory and asserts it is empty. Failed before the fix:
  `.../tmp/driver/52762-800 was handed out with 1 file(s) already in it`.
- `concurrent_scratch_calls_get_distinct_directories`: 16 threads x 50 calls, all distinct
  (guard; passed before and after).

Commands: `cargo test -q --test scratch` before the fix: 1 passed, 1 failed (as above).
No sleeps or timing anywhere.

## Fix

- `common::fresh_dir(kind)`: `create_dir` (exclusive) of `tmp/KIND/PID-COUNTER`; on
  `AlreadyExists` take the next counter. A directory is never shared and never cleared.
- `driver::scratch`, the `scratch` of `runner*.rs` and the `tmp_dir`/`wasm_dir` helpers of
  `integers`, `control`, `case_stmt`, `procedural`, `nested`, `routines`, `frames`, `skeleton`
  all use it. `skeleton.rs` gains `mod common;`.

## Verification

- `cargo test -q --test units --test scratch -- --test-threads=16`, 20 iterations: 20 passed.
- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`: clean.
- `make check`: exit 0, all test binaries ok.
- LOC budget: tests only, no `compiler/src` change.
