# #85 Harmless compiler switches and the M directive, #91 Lines longer than 126 characters

Branch: 85-harmless-compiler-switches-and-the-m-directive (carries both issues)

## Probed with tools/tp5.sh (the source of every expectation)

- Switch letters `A B D E F I L N O R S V` with `+` or `-` are accepted, in lists, in either
  case and in `(*$ *)`. Every other letter (`G C K Q T U W X Y Z H J M P`) is error 17, not 200.
  `{$A}`, `{$A,B}`, `{$A+,}`, `{$ A+}`, `{$AB+}` are 17. TP also tolerates `{$A++}`, `{$A+B-}`,
  `{$A+ ,B-}`, `{$A+;}`; this compiler keeps its strict list syntax there (D37).
- `{$M s,h1,h2}`: needs a blank after `M`; three numbers (decimal or `$` hex, blanks allowed
  around them); stack 1024..65520, heap sizes 0..655360; text after the third is ignored;
  `{$M 1024,5,3}` is accepted (min above max is not checked); anything else is 17. Accepted
  after `begin` too.
- Line length: a line of 127 bytes is accepted, 128 is error 11 at that line. The brief and
  swag.md say 126; the real limit is 127 (checked: 127 ok, 128 error, for a comment line and a
  code line). UTF-8 counts bytes (62 two-byte characters plus 3 = 127 ok, 63 plus 2 = 128 error).
  The line is checked when it is reached, so a long line after the final `end.` is never read;
  skipped (`$IFDEF`) text, a line inside a multi-line comment and a last line without newline are
  all checked. In an include or unit the error names that file.
