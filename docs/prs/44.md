# #44 Range checking

Branch `44-range-checking`. Stage 1 (RED).

## TP 5.0 probes (`tools/tp5.sh`, probes in `tmp/p`, not committed)

- **Granularity is per statement, in source order.** A `{$R+}` in the middle of a statement list applies to the
  statements after it; `{$R-}` switches it off again. A directive inside a routine stays in force for all code that
  follows textually, including the main body after the routine. A directive in a declaration part works the same.
- **Value arguments are checked by the call site**: `{$R-} P(i)` with an out-of-range `i` runs even if `P` was declared
  under `{$R+}`; `{$R+} P(i)` fails, and a call through a procedural variable is checked the same way.
- **Function results**: `F := x` inside the function is an ordinary assignment and is checked at the assignment.
- Checked: Integer to Byte/ShortInt/Word (`w := -1` gives 201), LongInt to Integer, Word to Integer, Byte to ShortInt,
  expressions (`b := b + c`), `Val(s, b, code)` into an out-of-range Byte (201, the assignment is checked), pointer
  targets, record fields, array elements, locals, array indexes of every index type (negative bounds, `Char`, enums),
  string indexes against the declared size (read and write, `String[3]` index 4, `String` index 256, index -1).
- **Not checked**: `Inc(b)` at 255 and `Dec(b)` at 0 for a Byte, `Inc(b, n)` (D17 keeps this). **Deviation:** TP does
  raise 201 for `Inc(s)` of the subrange `1..10` at 10; we do not (the rewritten assignment is never checked). To be
  recorded in `docs/deviations.md` at GREEN.
- `Succ(Sun)` of the last enum value is 201 under `{$R+}` in TP (and presumably `Pred` of the first). Not in the brief;
  not tested, not planned. Say if wanted.
- Directive syntax: `{$R+,F+}`, `{$F+,R+}`, `{$r+}` are accepted; `{$R}` and `{$R+,}` are error 17 (line of the
  directive). `{$R+ text}` is also accepted by TP (the corpus does not use it); not planned.

## How each fails today

Every program with `{$R+}`/`{$R-}`/`{$r+}`/`{$R+,F+}` is rejected with `Error 200: Feature not supported` at the
directive (all 51 listed lang/rt compile failures, plus the compile-API tests). The 5 neg programs report `200` instead
of `17`/`76`. `other_directives...` and `corpus_lists...` pass. No empty-versus-empty comparison: every lang `.out` is
asserted non-empty and every rt `.out` is asserted to end in `Runtime error 201`.

## Intended design (budget: checker at most 30 new lines, now 1588)

- Parser: `drop_directives` keeps the switch positions: `Ast::range: Vec<(line, col, on)>` (comma-separated items,
  `F+`/`F-` ignored, `R+`/`R-` recorded, `R` without sign or an empty item is 17, anything else 200).
- Codegen decides per expression node: `range_on(e)` = the last switch at or before the node's position is `R+`.
  System nodes (line 0) and synthesized nodes are therefore unchecked (the `Inc`/`Dec` assignment is built from `Inc`'s
  nodes, so its value node must be positioned at line 0 or typed as the variable, D17).
- One helper, `RangeChk(v, lo, hi: LongInt): LongInt` in System (calls `RunError(201)`), registered as a handle in
  `HELPERS` (two checker lines). Codegen pushes `lo`, `hi`, calls it: on assignment to an ordinal target
  (`Kind::Assign`), on value arguments in `push_args` (so procedural calls are covered), and on the index in `addr`
  (array bounds, strings `0..capacity`). A check is skipped when the source's static range lies inside the target's or
  when the value is a constant (the checker already reports 76).
