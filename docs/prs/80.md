### Interface the tests fix

Deviation from the brief, for the lead to confirm: **`ide/main.pas` is a unit `Main`, and the
program is `ide/ide.pas`** (`program Ide; uses Main; begin RunIde end.`, 4 lines). A program cannot
be `uses`d, so tests could not drive a program called Main with different keys and prefilled text;
with the unit they do exactly what the Files tests do (`Start('text'); RunIde;`). `RunIde`
returns when the user quits and the IDE program then ends by falling off its end (the same exit
code 0 as `Halt`), so a test can call `Report` afterwards to read files back. Both files are
counted IDE lines.

`unit Main`: `procedure RunIde;` only. It does `View.Reset; ResetKeys;`, then loops
`Paint; DrawBar; <file name on row 1>; Cmd := ReadCommand; if Cmd = CmdMenu then Cmd := Menu.Run(MenuLetter);`
and carries the command out:

- `CmdNew`: `NewFile; ResetKeys`. `CmdOpen`: `OpenFile; ResetKeys` (block marks must not
  point into replaced text, decision 49). `CmdSave`: `SaveFile`. `CmdQuit`: ends when
  `SaveIfModified`.
- **Title**: ` NAME ` right-aligned on row 1, attribute 70, written after `DrawBar`.
- **Compile (F9)**: `IdeHost.Compile(CurrentName, TextPointer, TextLength, Result)`. Success:
  status message `Compiled`. Error: `Error N: <text>` and, when `Result.FileName = CurrentName`, the
  cursor goes to `PosOf(Line, Col)` (the window scrolls through the usual `Paint`). An error in
  another file (unit or include) is named with its position and the cursor does not move:
  `U.PAS 7:11 Error 3: Unknown identifier`.
- **Error texts**: the contract returns a number, not a message. Decision: a nine-entry table in
  Main (2, 3, 4, 5, 10, 26, 37, 85, 94, the texts of `diag.rs`); any other number shows as
  `Error N`. A full table would be about 90 lines of data; the compiler's text cannot reach the IDE
  without widening the host contract (host glue is 600/600).
- **Run (Ctrl-F9)**: always compiles first (compile is fast, no staleness tracking; a module not
  made from the text on screen is never run). On a compile error: the error as above, no run.
  Otherwise `IdeHost.Run`, then `Exit code N - press a key` on row 25 (bar colour, rest of the
  row cleared), `ReadKey` (an extended key is swallowed with its second byte), then the screen is
  cleared to the bar colour and the loop repaints. The scroll position is kept (View is not
  `Reset`). The status message after a run is empty.
- View/Keys/Menu cleanups (all in GREEN): `CmdNew = 7` moves from Menu to Keys; `' Edit'` leaves
  View's placeholder (` File  Run  Compile  Options`); `View` exports `BarAttr` (Main and Menu used
  private copies) and a new `ClearScreen` (the part of `Reset` that clears; `Reset` calls it).

### How the goldens were made

The draft of the unit (`ide/main.pas`, `ide/ide.pas`, the three small edits) was written first
and kept at `tmp/draft/` (not committed); the 44 `.out` files, `ide_view_placeholder...` and
`ide_keys_cmdnew...` come from `tools/tp5.sh` with the draft in `ide/` and the stand-in IdeHost. With
the draft, this compiler gives the same bytes for all of them (`cargo test --test lang`: the only
failures are the 150 old goldens whose row 1 has `Edit`, see below) and `main_test.mjs` and
`idemain.mjs` pass (Chrome and Firefox). I read the dumps against the intent above. Draft
problems found: TP 5.0 does not allow a function call as a statement (`ReadKey;` is error 36
here, error 122 `Invalid qualifier` in this compiler; the draft uses a variable); the `uses`
word in a comment before the first `uses` would break `tools/tp5.sh`'s unit injection (avoided).

### Design decisions

- Main is a unit so that tests can prefill the Buffer; the program is `ide/ide.pas`.
- Run always compiles first. Error number without text shows as `Error N`.
- `TextReplaced` rather than turning `NewFile`/`OpenFile` into functions (function calls as statements are not TP 5.0).
