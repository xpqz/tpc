### Design the tests pin (new modules in `vscode/src/`, none imports `vscode`)

| Module | Interface |
|---|---|
| `screen_ansi.mjs` | `ENTER_SCREEN` (`ESC[?1049h`), `LEAVE_SCREEN` (starts with `ESC[?1049l`, then resets colours and shows the cursor), `attributeCode(attr)` -> `ESC[0;FG;BGm`, `createScreenWriter()` -> `{frame(grid), resize(columns, rows)}`. `frame` returns the text for the change since the previous frame, `""` when nothing changed |
| `terminal_text.mjs` | `inputBytes` extended: F1-F12 (also modified), Alt+letter (`ESC` + letter), modified arrows and navigation keys, Shift+Tab; same bytes as `keyBytes` of host/keys.js |
| `output_batch.mjs` | `createOutputBatch({post, now, intervalMs, limitBytes})` -> `{write(bytes), flushIfDue(), flush()}` |
| `run_session.mjs` | for a program that imports `screen`: `startRun` result has `grid` (Uint8Array on a SharedArrayBuffer, `undefined` for a plain program) and `resize(columns, rows)`; `onOutput` gets `ENTER_SCREEN`, frames (about 30 per second, only when the grid changed), then `LEAVE_SCREEN` and the end text. `CRT_MESSAGE` is removed |
| `run_terminal.mjs` | `open(dimensions)` and `setDimensions(dimensions)` feed `resize`; the pty is otherwise as before |

Decisions pinned here:

- Colours: DOS colour bits are swapped to ANSI order (DOS 1 blue is ANSI 34, DOS 4 red is 31); bit 3 of the
  foreground is the bright range 90-97. The blink bit (128) is a bright background (100-107), never the
  blink attribute: blinking text is rarely wanted in a terminal and many terminals ignore SGR 5.
- Every colour change is the full `ESC[0;FG;BGm`, so a frame never depends on the colour state a
  previous frame left behind.
- A frame is `ESC[?25l`, then for each run of changed cells one cursor move (`ESC[row;colH`), one
  colour change where the attribute changes and the glyphs, then a move to the grid's cursor and
  `ESC[?25h`. A frame where only the cursor moved is the move alone. After a write in column 80 the
  next cell gets a move, never the terminal's wrap.
- The first frame, and the first after the window grew, starts with `ESC[2J` (when it follows a
  notice) and draws every cell.
- A window under 80x25 gets one line ("Please enlarge the terminal to at least 80x25 ...") and no
  cells; frames are silent until it is big enough, then the whole screen is redrawn. The same size
  twice is no change.
- Sound and NoSound do nothing, Delay waits on the real clock (as in host/worker.js).
- The alternate screen is left when the program ends; the end text and "Press any key" are on the
  normal screen as in #106. A program that prints and ends therefore does not stay on screen.

### Design change from RED: ring instead of batch (needs approval)

The RED design batched in the worker and flushed before blocking calls and at the end. That cannot work:
the worker runs the program in one synchronous call, so no timer fires there, and a program that prints a
line and then spins or computes (the #106 tests `Ctrl+C stops a spinning program`, `close() terminates` and
`stop()`, using `spin.pas`) never flushes: the line stayed in the batch and those tests timed out (found by
`make check`). The output now goes through a shared ring that the extension reads on a timer, so latency
is bounded by 20 ms with no cooperation from the program, a ReadLn prompt needs no flush, and a fast
writer waits on a full ring instead of filling memory. `output_batch.mjs` and `output_batch.test.mjs`
(unit tests of the batch only) are deleted and replaced by `output_ring.test.mjs` (7 tests: order, wrap,
exact fill, 32-bit counter wrap, random writes and reads). `output_flood.test.mjs` is unchanged and passes.
`usesCrt` returns false for a module that does not parse, so the worker reports the load error.
