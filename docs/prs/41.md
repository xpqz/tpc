### Why each fails today

test (it asserts files and counts only).

### Intended behaviour (for the RED verdict; not implemented)

- `set of T`: `Type::Set(base)`, 32 bytes, bit i of byte i/8 = element i; base must be an ordinal within 0..255
  (23 for an out-of-range subrange or `Integer`/`Word`, 29 for a non-ordinal such as `String`). Passed by address like
  aggregates (add it to `is_agg`, so `memory.copy` assignment, value/var parameters, frame copies and fields come free);
  `binary` handles sets before its aggregate rejection: `+ * -` give the same set type (26 on a base mismatch), `= <> <= >=`
  give Boolean, everything else 41; `in` (left ordinal compatible with the base, right a set: 26 / 41).
- `[a, b..c]`: new node `SetLit(List)` with ranges as `Range` nodes; type is a set of the element family (`[]` is
  compatible with every set). Codegen builds it in a frame temporary (same mechanism as string temporaries, `new_temp`)
  by zeroing 32 bytes then one `SetAdd(var d; lo, hi)` helper call per item; set results of `+ * -` go into a temporary
  too, so `(a + b) * c` needs no special case.
- Helpers in `runtime/system.pas` (Pascal, bound by handle like `StrCat`): about four small routines, `SetOp` for
  `+ * -` (d, a, b, op), `SetAdd` (range), `SetIn`, `SetLe` (`=` is `SetLe` both ways; `>=` swaps operands). Estimated
  System +25 lines.
- Untyped set constants: a `Const` symbol of set type whose value is the constructor node; a use re-emits the constructor
  (no data section). Typed set constants stay Phase 5.
- Target: checker +50 lines at most (decision 22); pruned at RED already: `set of LongInt` (TP5: 29, versus 23 for
  Integer), `set of set`/`array`, `s and s` beside `s div s`, `1 in` with a missing operand, an element outside the
  base subrange (TP5 accepts `[7]` in `set of 1..5`), and Real-bearing negatives. If error 76 for `[300]` costs lines
  beyond a reuse of the existing constant range check, prune `own neg/set_element_over_255_constant`.
