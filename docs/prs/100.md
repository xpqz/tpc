# #100 Utils unit for routines SWAG programs define themselves

Branch: 100-utils-unit. Decision 53.

## RED

LOC before (tools/loc.sh): System, Crt, Dos subset 1442 / 1700; total 11478 / 15000.

### Oracle method
Expected output needs the real TP 5.0 to compile the unit, so a draft of `runtime/utils.pas`
was written first (kept out of this commit, in git-ignored `tmp/utils.pas`) and every `.out`,
`.err` came from `tools/tp5.sh` with `NAME.dirs` naming `runtime/utils.pas`. The outputs were
read through by hand for sanity. TP 5.0 findings that shaped the unit: a constant string
cannot be subscripted (typed constant `HexDigits: String` is used) and a function result
cannot be subscripted (tests copy it to a variable first).

### Tool change
`tools/tp5.sh`: a `.dirs` line naming a file copies just that file (header comment updated).
`compiler/tests/driver/mod.rs` `aux_dir` does the same for the Rust runner. Fixture
`tests/tools/fixtures/tp5/dirs_file.{pas,dirs}` and a check in `tests/tools/tp5_test.sh`
(passes now: `sh tests/tools/tp5_test.sh`, "NAME.dirs line naming a file copies only that file").

### Tests (all with a `.dirs` line `runtime/utils.pas`)
tests/lang:
- `utils_power_fractional_integral_and_zero`: fractional, integral, negative exponent, base 0/1, exponent 0, negative base with odd/even/negative exponent.
- `utils_trig_and_log_values`: Tan, ArcSin, ArcCos (including the poles +-1), Log10 incl. powers of ten.
- `utils_hex_digits_and_twos_complement`: Digits 0..255, truncation, -1 at 1/2/4/8, MaxLongInt, MinLongInt.
- `utils_trim_blanks_and_control_characters`: empty, all blank, tabs, control and NUL chars, chars > 127 kept, 255-char strings.
- `utils_upper_and_lower_case_ascii_only`: non-letters, chars 128..255 unchanged, exactly the 26 letters change.
- `utils_min_and_max_at_longint_extremes`
- `utils_leading_zero_widths_signs_and_overflow`: width 0, too small, zero, negatives (zeros go after the sign, the sign counts), MinLongInt, width 255.
- `utils_own_declaration_wins_over_unit`: own Power, Max, a variable Trim; `Utils.Trim` still reachable.
- `utils_uses_utils_in_a_unit_and_the_program` (+ directory with `WRAP.PAS`, a unit that uses Utils).

tests/rt (runtime error 207, as TP): `utils_power_negative_base_with_fraction_is_runtime_error`,
`utils_power_zero_base_negative_exponent_is_runtime_error`,
`utils_arcsin_out_of_range_is_runtime_error`, `utils_log10_of_zero_is_runtime_error`.

tests/neg: `utils_routine_without_uses_clause` (3 line 3), `utils_name_unknown_when_only_crt_is_used`
(3 line 4), `utils_hex_with_one_argument` (87 line 4), `utils_min_with_three_arguments` (89 line 4),
`utils_power_with_string_argument` (26 line 4), `utils_trim_result_assigned_to_integer` (26 line 6),
`utils_routine_not_listed_in_interface` (3 line 4), `utils_qualified_name_that_utils_lacks` (3 line 4).

### How they fail today
`tp5c` on each lang/rt program and on the six neg programs that say `uses Utils` reports
`(2,6): Error 15: File not found` (unit missing), instead of compiling. The two neg programs
that do not use the unit (`routine_without_uses_clause`, `name_unknown_when_only_crt_is_used`)
already pass: they guard that Utils names are not visible without `uses Utils`.

### Intended behaviour
See decision 53 and D47. `Power(0,0)` and `Power(x,0)` are 1; `LeadingZero` pads zeros after
the sign and never truncates.
