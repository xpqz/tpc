# #18 Phase 1 test corpus

Branch: `18-phase-1-test-corpus`. Test files only, no implementation stage; nothing under a
counted path changed (LOC delta 0). Every program is listed in `tests/lang/PENDING` or
`tests/neg/PENDING` because no compiler stage exists yet.

## Method

- `tests/lang/NAME.pas` + `NAME.out`: every `.out` was generated by `tools/tp5.sh` (real
  Turbo Pascal 5.0 under DOSBox-X), never by hand. Run for all programs in parallel with a
  scratch script in `tmp/`. All 118 compiled and ran under TP5. The same programs were also
  built with `fpc -Mtp -v0` (3.2.2) for comparison (see below).
- `tests/neg/NAME.pas` + `NAME.err` (`N LINE`): every `.err` copied from the line
  `tools/tp5.sh` prints (`P.PAS(LINE): Error N`), except the `unsupported_*` group (our
  error 200, expected line = line of the offending construct).
- Phase 1 constructs only (plus the intrinsics noted below). No `{$R+}` use.
- Programs were drafted against decision 5; the first draft's expected outputs for
  int_typing were derived by hand, then replaced by TP5's output on the lead's instruction.
  My hand derivations of 11 expected outputs agreed with TP5 on 8; the three that did
  not are the byte-sized shift cases covered by decision 10 (`Byte shl` widens to
  Integer, `ShortInt shr` sign-extends first) and `-Word` (LongInt), all decision 10.

Arithmetic for the differing rows (TP5 values confirmed by `tools/tp5.sh`): Byte*Byte
200*200 = 40000, as Integer 40000-65536 = -25536; 255*255 = 65025 - 65536 = -511.
`(30000+30000) div 2`: 60000-65536 = -5536, div 2 = -2768, mod 7 = -6, `> 0` FALSE.
Word 65535+1 = 65536 mod 65536 = 0; 1-65535 = -65534 mod 65536 = 2; 80000-65536 = 14464,
div 2 = 7232. Byte 255 * Word 65535 = 16711425 mod 65536 = 65281. LongInt 2^31 wraps to
-2147483648; 65536*65536 = 2^32 wraps to 0; (2e9+2e9) = 4e9 - 2^32 = -294967296, div 2 =
-147483648. Integer 200*200*200: 40000 -> -25536; -25536*200 = -5107200 mod 65536 = 4608.
`Byte*Byte + LongInt`: -25536 + 200 = -25336; `-25536 div 7` = -3648.
`Byte(200) shl 1` = 400 (widened to Integer, decision 10); `Word($FFFF) shl 4` = 65520;
`Integer 16384 shl 2` = 65536 wraps to 0. `ShortInt -128 shr 1` = 32704 (sign-extended
$FF80, logical shift in 16 bits), `ShortInt -1 shr 7` = 511.

## Other fpc versus TP5 differences

fpc and TP5 produced the same output for every other lang program except:
- `case_longint_selector_is_integer_sized`: TP5 `integer range / negative`, fpc `integer range / other`

Findings from running TP5 while writing the corpus:
- `case` labels are limited to the Integer range: `32768..65535` for a Word selector and
  `-2147483647..-1` for a LongInt selector are Error 112 in TP5. The programs use labels
  within -32768..32767.
- A LongInt `case` selector is truncated to 16 bits (`case_longint_selector_is_integer_sized`:
  100000 selects the `-32768..-1` arm). The program pins TP5's behaviour; the lead may
  decide to drop it or record a deviation.
- TP5 does not report duplicate case labels and does not range-check case labels against a
  ShortInt selector (`case s of 200:` compiles); fpc rejects duplicates. No negative test
  exists for either.
- TP5 reports the line of the lookahead token for errors found at the end of a statement:
  type mismatches and out-of-range constants on a statement that is the last on its line
  are reported on the following line when the next token is on the next line (for example
  `type_mismatch_boolean_to_integer` is line 5 though the assignment is on line 4).
- fpc: a `for l := -2147483646 downto -2147483647 - 1` loop with constant bounds printed
  only the first value, so the program uses a variable bound (fpc is not the oracle now).
- Intermediate overflow: `for_accumulate` first summed `i*i` up to i = 1000, which wraps in
  16-bit; bound reduced to 180 so no intermediate overflow is involved.

| `unterminated_string` | 8 | 3 | `WriteLn('abc);`. fpc: String exceeds line (2001), line 3. |

Dropped after TP5 accepted them: `duplicate_case_label`, `case_label_out_of_range_byte`,
`case_label_out_of_range_shortint`. Not written: error 37 (END expected), which TP5 did not
produce for either missing-end flavour; wrong number of parameters (TP5 has no dedicated
error: 87 for too few, 89 for too many, both measured).

Missing end: TP5 reports 10 when the file ends inside the block, and 85 (";" expected)
when `.` follows the last statement. TP5 never reported 37 in these programs.

Unsupported group (`unsupported_*`): TP5 accepts `absolute`, `inline` (both forms),
`interrupt` and `Single` and rejects `goto`, `label` and `asm` with different errors, so the
expected number is our error 200 (decision 6) and the line is the offending construct's
line. These cannot be oracle-checked. `for_control_variable_real` and
`ordinal_expression_expected_case_real` use `Real`, which Phase 1 does not require; they are
valid TP5 negatives but the compiler needs the type declared to reach those errors.
