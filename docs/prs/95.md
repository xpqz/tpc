## Waste found

1. **Compiler release module carries a 55,001 B `name` section** (plus 230 B producers and
   target_features). Cargo's release profile has no `strip`. `docs/size.md`'s "stripped" column is
   what the module would be with this fixed. Fix: `strip = true` in `[profile.release]`, 0 Rust
   lines. Unstripped 309,789 B becomes about 254,558 B.
2. **`write_integer` (99 B) and `quotient` (75 B) are defined in every module** (`emit_builtin_functions`),
   and `rterror` is imported in every module, because `mark` seeds `HostRtError` for them. Only
   `real_quotient` is conditional. Hello-world uses none of the three: about 200 B of 875 (function,
   type and import entries included). Fix: reach them on demand, the way `uses_real_div` does;
   estimated +15 to 25 Rust lines in `codegen.rs` (1615 / 2100 now), fewer if the three flags
   become one small `Builtins` record.
3. **Every procedural type becomes a WASM type** (`register_procedural_types`), used or not. Hello-world
   carries System's `ConsoleLineReader` `(i32,i32)->i32`, which nothing calls (1 of 7 types, 6 B);
   a program that declares an unused procedural type carries its signature too. `ConsoleWriter`
   is used (`TextFlush` calls through `ConsoleOut`) and stays. Fix: the mark phase records the
   procedural types a `call_indirect` uses and the emit phase registers only those; about +8 lines.
   Duplicate type entries do not occur: `Module::ty` already shares identical signatures.
4. **Embedded Pascal sources in the compiler**: the data section is 84,506 B, of which the five
   `runtime/*.pas` files are 59,187 B and about 21 KB of those are comments and blank lines.
   Stripping them in a `build.rs` would cost about 25 counted lines and a build step; not proposed
   unless the lead wants the compiler under 250,000 B (it is 4.6 KB over that reading).
5. **Zero tails of data segments**: hello-world has 2 B, the IDE 36 B in total. Typed-constant
   images pad strings to capacity, so IDE segment 4 holds 1,994 zero bytes inside 3,822; splitting
   a segment at long zero runs (memory starts zero) could save about 1.5 KB of the IDE for about
   10 lines. Optional; the IDE is at 21.6 KB of 120 KB.
6. **Name/custom sections in compiled programs and the IDE: none.** `Module::finish` writes none.
7. **Surviving in hello-world**, from the function sizes (39 99 75 117 62 43 45 123 30 3): the three
   built-ins `write_string`, `write_integer`, `quotient`; System's `TextOut`, `ConsoleWrite`,
   `TextFlush` (reached from `TextOut`/`ConsoleWrite`), `TextNewLine` and one more helper reached by
   `WriteLn`; the main program (30 B) and the trap stub; imports `write`, `fs_write` (called by
   `TextOut`) and `rterror` (item 2). An empty program is 718 B for the same reason: `write_string`
   needs `TextOut`, so output support is always present; this is not waste for any program that
   writes. Not proposed for removal.

Proposed fixes, each its own commit with before/after: (1) `strip = true`; (2) on-demand
`write_integer`, `quotient`, `rterror`; (3) used procedural types only. Items 4 and 5 are left to
the lead.

## Test that is wrong

`hello_world_does_not_import_rterror` (approved RED) cannot pass. `WriteLn` is followed by
`CheckIo` (`runtime/system.pas`), which calls `RunError`, which calls the `rterror` import, so a
pending I/O error is raised after console output too (TP semantics, `InOutRes`). Every program
that writes reaches `rterror` legitimately; an empty program (521 B) does not import it. The
assertion should be removed or changed to the empty program. I left the test unchanged for the
lead: it is the only failure of `make check` (`cargo test --test size_pass`: 10 passed, 1 failed).
The other 10 pass, including the type, function-count and 732 B tests (bound = 697 B plus 5%; the
final size is 691 B).
