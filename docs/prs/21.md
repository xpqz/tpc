### How they fail today

All four content tests fail on a compile error from the skeleton parser (36 "BEGIN
expected" at the first `var`/`const` line, 42 at integer arguments, 3 at `Frobnicate(3)`
after a 42): 51 of 51 lang, 26 of 26 neg, 18 of 18 `RUN`, all `ERR` cases. Not a harness

### Oracle findings (TP5 behaviour the tests pin)

- TP reports a type error at the token after the offending expression, so an assignment
  error is on the following line (the `end`): `i := 'ab'` is 26 at the `end` line.
- `Boolean + Boolean` is 41, `Char + Char` is 26, `not Char` and `and` on Char are 41,
  `1 shl Boolean` is 26, a non-integer field width is 38.
- A variable named like the program is Duplicate identifier (4). The program name is a
  declared identifier.
- Uninitialised globals are not zero in TP5 (garbage), so no test reads one.
- `a div b` with b = 0 at run time is `Runtime error 200`; not tested here (tests/rt owns it);
  GREEN should call `host.rterror(200)`.
- Error 133 (const initialised from a variable) and 21 are not in `diag::TABLE`; not tested.

### Design note: where main-program variables live

Main-program variables go in static data (plan §4.3), not WASM locals: nested routines
and `var` parameters in later slices reach globals by address, and a local-based scheme
would need a second code path and a migration. Addresses are assigned after the string
literals starting at 256 (sizes per abi §2, no padding); linear memory starts zeroed, so
globals read as 0 (TP leaves them undefined, so no deviation needs recording). Loads
sign- or zero-extend per type, stores truncate.
