# #39 Phase 4 test corpus

Branch: `39-phase-4-test-corpus`. Test files plus a small driver extension (test code, uncounted). LOC before and
after: `tools/loc.sh` total 4272 / 15000, delta 0.

## Method

- Every `.out` and `.err` was produced by `tools/tp5.sh` (real TP 5.0 under DOSBox-X) on the committed `.pas`. No
  expectation is hand-written and fpc supplied none. Generator scripts live in `tmp/` (git-ignored): a bundle
  splitter, `gen.sh` (writes `.out`, records compile errors), `genrt.sh` (adds the normalisation below), `genneg.sh`
  (`.err` as `N LINE`). Programs TP5 rejected were fixed or dropped.
- `tests/rt/` format: `STEM.pas`, `STEM.out`, `PENDING`. TP5 prints `Runtime error N at XXXX:YYYY.`; the `.out` files
  are normalised to our runner's `Runtime error N` (docs/abi.md section 8, no address) by stripping the
  ` at XXXX:YYYY.` suffix. Output before the error is kept, including a partial line: TP5 prints the error text directly
  after it with no separator (`partial lineRuntime error 200`) and so does `rterror`. The expected exit code is N from
  the last `.out` line.
- Driver: `check_rt` in `compiler/tests/driver/mod.rs` (same sweep and PENDING rules as `check_lang`; stdout compared to
  `.out` through `tests/run.mjs`, exit code must be N). `compiler/tests/lang.rs` gains
  `runtime_error_corpus_has_no_unexpected_results` and two driver tests on fixtures `compiler/tests/fixtures/rt/exit_mismatch`
  and `compiler/tests/fixtures/rt/no_error_line`.
- Decisions applied: 18 (MemAvail/MaxAvail only as relations; no address or count printed), 19 (Real values exact in
  both representations, or computed values that agree with fpc), 21 (no Include/Exclude except one negative), 22 (one
  negative per rule: 90 probed, 40 kept). D5/D6: no `SizeOf` of sets or pointers is printed.
- Counts: tests/lang 93 new, tests/abi 12 new, tests/rt 28 new, tests/neg 40 new.
- Already passing with the current compiler, so not in PENDING: lang `odd_abs_and_integer_funcs`,
  `rangecheck_off_by_default_wraps_and_keeps_low_bits`, `upcase_chars`; rt `div_by_zero_integer`, `div_by_zero_longint`,
  `div_by_zero_mod`. All other new programs are in PENDING (new lines: lang 90, abi 12, rt 25, neg 40).
- `make check` passes.

## TP5 findings

1. **Decision 20 is contradicted for string indexes.** Under `{$R+}` TP5 checks a variable string index against the
   declared size: `s[i]` with `i = 4` on `String[3]` is runtime error 201 (read and write); `i = 3` and `i = 0` run;
   `String[255]` with `i = 300` is 201; `t[6]` on `String[5]` is 201. A constant `s[4]` is compile error 76. Pinned by
   `rt/range_string_index_beyond_declared_size` (201) and `lang/rangecheck_string_index_within_declared_size` (indexes
   0..n pass). The lead should reconcile decision 20 or prune the rt test.
2. Set types cannot be function results (Error 34), `neg/set_function_result_type`. Set value and `var` parameters work.
   `c in []` with a Char left operand is Error 26 (not tested).
3. `Include` and `Exclude` are Error 3 (decision 21).
4. `Int`, `Frac`, `Pi`, `Swap`, `Hi`, `Lo`, `Odd`, `Inc`/`Dec` with step, and `Inc`/`Dec` on enums and chars exist. `Val`
   accepts `$FF` hex and a leading blank (`' 12'` is fine, `'12 '` is error at 3); `'1.'` and `'.5'` are valid reals.
5. `Val` into Integer without range checks wraps instead of failing (`'32768'` gives -32768 code 0, `'99999'` gives -31073
   code 0); into Byte `'256'` gives 0 code 0; into Word `'-1'` gives 65535 code 0; into LongInt `'2147483648'` is error at
   10 and `'-2147483648'` error at 11. Isolated in `lang/val_out_of_range_quirks_without_range_checks` so it can be
   pruned alone.
6. `Str(x:w, s)` into `String[3]` truncates; `Str(1024:0:0, s)` is a syntax error (integers take one width).
7. `Round` is half away from zero (`Round(2.5)=3`, `Round(-2.5)=-3`); fpc rounds half to even. `Write(x:w:d)` rounds exact
   ties away from zero (`0.125:0:2` gives `0.13`, `-0.125` gives `-0.13`, `2.5:0:0` gives `3`).
8. `Write(x:w)` without decimals prints scientific with the fraction digits that fit the width (`x:12` gives
   ` 1.23450E+03`, `x:8` and below give one fraction digit, `x:20` gives ten). `Write(x:0:0)` of 2^64 shows 11
   significant digits then zeros (TP5 digits, not f64 digits); that line was dropped.
9. Integer typing as in decision 10: `w + 1` with `w: Word = 65535` is 0, `Sqr(300)` is 24464. fpc differs, so these lines
   are not cross-checked.
10. `ParamStr(0)` is the program path (non-empty) in TP5; only `ParamCount = 0` and `ParamStr(n) = ''` for n >= 1 are
    tested.
11. Runtime 204: `Dispose(nil)`, `FreeMem(nil, n)`, `Dispose(@stackvar)`, a wild pointer `PI(1)` and a second `Dispose` of
    the same pointer are all 204. `Dispose` of a block after `Release` is not an error, `GetMem(p, 0)` works, reading
    `p^` for nil does not halt. `pointer_dispose_twice` needs free-list or heap-top detection; the lead may prune it.
12. Runtime 203 is reached by allocating until failure with `New` of 1008-byte records or `GetMem(p, 60000)`; nothing
    printed depends on the count. `heap_overflow_after_release_succeeds_then_fails_again` loops `while MaxAvail >= 30000`
    before each `Release`, so it holds for any heap above 30000 bytes.
13. Real division by zero (`1 / x` with x = 0) is 200.
14. After `Mark`, `Release` discards freed blocks above the mark: `MemAvail` returns exactly to its value at `Mark`
    (`heap_release_discards_freed_blocks_above_mark`). `New`, `Dispose`, `New` of the same size returns the same pointer
    (`heap_new_dispose_reuses_freed_block`).
15. A variable named like a type (`pr` and `PR`) is Error 4; `^String[5]` is a syntax error.

## Real programs: how each was checked

fpc `-Mtp` (`SizeOf(Real)` = 8) output was compared with the TP5 `.out` for every Real program with no default
(scientific) format. Same: `real_accumulate_in_loops`, `real_arrays_and_records`, `real_comparisons_and_mixed`,
`real_compound_interest_computed`, `real_constants_and_literals`, `real_function_parameters_and_results`,
`real_int_frac_and_pi`, `real_newton_iteration_computed`, `real_slash_always_gives_real`,
`real_sqrt_irrational_to_few_digits`, `real_write_mixed_with_other_types`, `real_write_rounding_of_exact_ties`,
`real_write_width_and_decimals`. Different, none because of a Real digit: `real_integer_promotion` (Word wrap),
`real_round_and_trunc` (fpc rounds to even), `real_sqrt_sqr_abs` (`Sqr(300)` 16-bit), `real_mixed_longint_arithmetic`
(`l * 0.5` with `l = 123456789`: TP5 gives the exact 61728394.5, fpc 61728396.0; the value is exact in f64). Programs
printing the default format use values exact in both representations: `real_arithmetic_exact_values`,
`real_write_default_format`, `real_negative_values_formatting`, `real_large_and_small_exponents` (powers of two up to 2^100
and 2^-40), `real_zero_and_signs`, `real_write_width_without_decimals`.

No program was dropped for differing digits. Changed or removed material:
- compound interest used rate 0.05, whose 1000 * 1.05^3 = 1157.625 is a decimal tie that rounds by representation;
  changed to 0.0625.
- 2^64 with `:0:0` (TP5 shows 11 digits then zeros, f64 shows all digits): line removed.
- `-z:0:1` with `z = 0` (f64 negative zero has no TP5 equivalent): line removed.
- `3.` as a literal and `1E;`: TP5 rejects the first and accepts the second oddly; removed.
- Transcendentals exist in TP5 but are outside plan scope and unused.
