# #27 Phase 2 test corpus and sp-restoration harness

Branch: `27-phase-2-test-corpus-and-sp-restoration-harness`. Test files, driver and runner
change only; nothing under a counted path changed (LOC delta 0, `tools/loc.sh` total 2621 / 15000).

## Method

- Every `.out` and every `.err` was produced by `tools/tp5.sh` (real Turbo Pascal 5.0 under
  DOSBox-X) on the committed `.pas`; nothing is hand-written and fpc was not used. `.err` is
  `N LINE` from the compiler's `P.PAS(LINE): Error N` line. Scratch generator scripts lived in
  `tmp/` (git-ignored).
- Phase 2 scope only: var parameters, nested routines, static-link access, `Exit`,
  recursion, procedural types/variables/parameters, function results. No arrays, records,
  strings, sets, pointers or `Real`. `Inc`/`Dec`/`nil` are not used.
- Programs that use procedural values start with `{$F+}` (see findings).
- `tests/abi/PENDING` (50 programs), `tests/lang/PENDING` and `tests/neg/PENDING` list the new
  programs that the compiler on this branch does not yet pass. 20 of the new programs
  (listed below as "passes now") already pass against the current compiler (`Exit`,
  forward declarations, plain recursion, function results from #24) and are therefore not
  pending; the driver would fail on a pending program that passes.
- Recursion depth is at most 1500 (`recursion_deep_function`); all programs ran under TP5's
  default 16K stack.

## Runner: `sp` restoration

`tests/run.mjs`: if the instance exports `sp` (a mutable global), its value is read before
`main` and compared after `main` returns normally; a difference throws a `RunnerError`
(`run.mjs: sp not restored: A before main, B after`, exit 2, output so far kept). Not checked
after `halt` or `rterror`, and not checked when there is no `sp` export (modules without a
shadow stack).

Tests (`compiler/tests/runner.rs`, fixture module built with the emitter by `sp_module`):

| Test | Checks | RED state before the `run.mjs` change |
|---|---|---|
| `sp_restored_by_main_passes` | main leaves sp unchanged: exit 0, no stderr | passes (control) |
| `sp_not_restored_is_a_runner_error` | sp lowered by 16 and raised by 4: exit 2, message, stdout kept | FAILED: exit 0 |
| `sp_not_restored_is_an_error_in_print_mode_too` | same without an expected file | FAILED: exit 0 |
| `sp_is_not_checked_after_halt` | sp changed then `halt(3)`: exit 3, no stderr | passes (control) |
| `module_without_sp_export_is_not_checked` | no `sp` export, global changed: exit 0 | passes (control) |

Commands: `cargo test --test runner sp_` before the change: 3 passed, 2 failed (the two
above, for the stated reason: exit code 0 instead of 2). After: `cargo test --test runner`:
31 passed.

## TP5 findings

- **`{$F+}` is required to assign a routine to a procedural variable or pass it as a
  procedural argument, even for a top-level routine.** Without it every such use is Error 143
  "Invalid procedure or function reference" (checked: global, nested, parameter). The switch
  is per routine: a routine declared under `{$F+}` and followed by `{$F-}` stays assignable,
  a routine declared under `{$F-}` is rejected (`proc_type_per_routine_far_directive`).
  Calling through a variable declared as a procedural type needs no switch. The `far`
  directive does not exist in TP5 (`procedure A; far;` is Error 36 "BEGIN expected").
  Every program using procedural values therefore starts with `{$F+}`. Our compiler may
  ignore `{$F+}`; no negative test depends on its absence (a test expecting 143 without
  `{$F+}` would contradict that), and no test uses `{$F-}` to reject a routine.
- **Nested routines cannot be assigned or passed as procedural values**, with or without
  `{$F+}`: Error 143, at the assignment or call-argument line (procedure and function,
  local or global target, two levels deep, as argument): the plan's "nested-routine
  assignment error" is number 143.
- **`@` on a routine is not accepted** where a procedural value is expected:
  `p := @A` and `Use(@Id)` are Error 20 "Variable identifier expected". (`@p := @A` compiles
  in TP5 but is pointer-typed assignment and out of Phase 2 scope; not tested.)
- **A procedural variable of procedure type cannot be compared**: `p = q` is Error 143
  (the bare identifier is treated as a call). A procedure used as an expression value
  (`n := P`) is also 143.
- A bare function name on the right-hand side of an expression is a call, so
  `Late := Late + i` inside function `Late` is Error 88 "(" expected (no recursion without
  parentheses). Programs use a separate accumulator.
- Signature mismatch on assignment or argument passing is Error 26 "Type mismatch"
  (parameter count, parameter type, result type, procedure vs function, var vs value
  parameter). Two differently named procedural types with an identical signature are
  assignment compatible (structural): `proc_type_structural_compatibility`.
- Passing something other than a procedure to a procedural parameter or variable
  (`p := 5`, `Use(3)`) is Error 20.
- **Var parameter arguments:** a constant, named constant or char literal is Error 20; an
  expression such as `n + 1` is Error 89 `")" expected` (the parser stops at `+`); a function
  call is Error 122 "Invalid variable reference"; a variable of a different type, even
  Byte/Integer, Word/Integer or Integer/LongInt, is Error 26 (types must be identical).
  Too few arguments is Error 87 `"," expected`, too many is Error 89 `")" expected`.
  Calling a procedural variable with the wrong argument count: 87; wrong type: 26.
- `Exit(1)` is Error 85 `";" expected`; `n := Exit` is Error 42. `F := 2` for a function
  `F` outside its body is Error 122.
- **Assigning an enclosing function's result from a nested procedure is accepted by TP5**
  (`function F ... procedure Helper; begin F := 5 end; ...`). No test: undocumented
  behaviour we do not need to copy; the lead may add it to `docs/deviations.md` if our
  checker rejects it.
- Nested duplicate names are Error 4 ("Duplicate identifier"), an unsatisfied nested
  `forward` is Error 59 reported at the `begin` of the enclosing routine
  (`nested_forward_never_defined`: line 4), and a nested routine used
  before its declaration is Error 3.
- `Set` is a reserved word (not usable as a routine name).
- Array-free procedural "tables" are not possible; indirect calls in loops use a selected
  variable (`proc_var_chosen_by_condition`, `proc_var_reassigned`).
- Argument evaluation is left to right (`args_evaluated_left_to_right_with_side_effects`
  pins TP5's output for `Show(g, Next, g)`: value argument `g` is evaluated before `Next`
  runs).
- Timing hazard noted while writing: a doubly recursive function with four recursive calls
  per level made `tools/tp5.sh` run for minutes; programs are kept to cheap recursion.

## Not in this corpus

- Misuse of procedural values without `{$F+}` (143), see above.
- `@f := @A` and anything pointer-typed.
- Runtime checks of `sp` inside the Pascal programs: the harness checks it from the
  `sp` export at program end; the `.pas` programs do not mention it.
