## Measurements

All with `fpc -Mtp -v0` (3.2.2, aarch64) built in `tmp/` (git-ignored, not committed).
Programs: `tmp/promo.pas` (mixed-width arithmetic, assignment truncation, shifts, `not`),
`tmp/promo2.pas` (expression value used without assignment), `tmp/ovf.pas` and
`tmp/rng.pas` (`{$R+}` range errors: both exit 201), `tmp/sz.pas` and `tmp/pk.pas`
(`SizeOf` of enums, subranges, sets, records, strings, pointers). Results are in
`docs/abi.md` Open questions 1 to 9 and deviations D5 to D7.

Headline: fpc evaluates 16-bit expression operands in wider arithmetic and truncates only
on assignment (`sizeof(b+b)` is 8; `(i+i2) div 2` with 30000+30000 is 30000). It therefore
cannot confirm the plan §4.6 rule "re-narrow after `+`, `-`, `*` when the result type is
16-bit or narrower" for unassigned expressions, and does not tell what the TP result type
is. Assigned (truncated) results match §4.6.

Commands run: the fpc builds and executions above; `git status` check. No tests exist for
this issue.

## Open questions (full text in `docs/abi.md`)

1. Result type of `Byte+Byte` and the other mixed-width pairs; fpc is not an oracle (TP5
   manual needed). Blocks codegen.
2. Unary minus on `Word`/`Byte` and `Integer` vs `Word` comparison types.
3. Whether `shl`, `shr`, `not` re-narrow.
4. Signedness of subranges and enum size boundaries (confirm assumption).
5. Set size 32 vs fpc minimal; record padding; pointer size (D5 to D7).
6. `String` default capacity; `result_ptr` for non-string/set aggregates.
7. Static data order, initial `sp`/`HeapPtr`/`HeapEnd`.
8. `Halt` / `rterror` exit flow and codes.
9. `host.write` fd values, `screen` ops, `fs_open` modes, `time` unit, error returns.
10. Element table layout beyond index 0; where `HeapPtr`/`HeapEnd` live.
11. `{$R}` default (assumed `-`); other switches accepted, ignored or rejected.
12. Error numbers for omitted features.
