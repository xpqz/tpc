# #19 LOC gate rejects lines over 100 columns

Branch: `19-loc-gate-rejects-lines-over-100-columns`.

## RED stage

### Intended behaviour

`tools/loc.sh` prints `LONG: <path>:<line> (<N> columns)` for every line longer than 100
columns in a counted file and exits 1. `<path>` is relative to ROOT (as `UNASSIGNED:`);
N is the line length in characters. Rust is judged on the rustfmt'd copy, since rustfmt
wraps what it can and only unbreakable literals remain. Comment-only lines are included.
Files outside the budget components are not checked.

### Tests (`tests/tools/loc_test.sh`, fixtures in `tests/tools/fixtures/long/`)

| Test | Checks | Today |

| long: 101 columns flagged in Rust, Pascal and JS | `over/` (line 4, 4, 2): exit 1 and three exact LONG lines | FAIL: exit 0 |
| long: comment-only lines are flagged | `comment/` (101, 105, 101 columns): exit 1 and LONG lines | FAIL: exit 0 |
| long: exactly 100 columns passes | `exact/`: exit 0, `LongExact: 14 / 100` (non-empty report) | pass (guard) |
| long: no LONG at 100 columns | report present, no LONG text | pass (guard) |
| long: Rust judged after rustfmt | `wrapped/a.rs` has a 101-column raw line that rustfmt wraps: exit 0, `Wrapped: 6 / 100` | pass (guard) |
| long: no LONG when rustfmt shortens | report present, no LONG text | pass (guard) |
| long: files outside the budget ignored | `uncounted/` (150-column .rs and .txt) not in `long_uncounted.txt`: exit 0, `Counted: 15 / 100` | pass (guard) |
| long: no LONG for uncounted files | report present, no LONG text | pass (guard) |

Expected counts were done by hand (Rust 6 = formatted lines, Pascal 5, JS 3). The Rust
over/exact fixtures are rustfmt-clean with the literal on its own line (8-space indent),
so the formatted line is 101 / 100 columns.
