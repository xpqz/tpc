# 103: worker.mjs sleep test is timing-flaky under load

Branch: 103-worker-sleep-test-flake. Test-only; no host/ or compiler change.

## Cause

The test measured `sleep(50)` as the gap between two moments the main thread's 5 ms poll saw
grid changes ("a" and "a1"). Under load the poll sees "a" late, after the sleep has begun, so
the gap shrinks ("slept 28 ms"). host/worker.js is correct: its clock `advance` is
`Atomics.wait(pause, 0, 0, ms)` on a word nobody notifies, so it returns only on timeout and
cannot return early.

## Change (tests/host/worker.mjs)

The test waits 200 ms so the worker is blocked in readkey, takes `pushed = Date.now()`
immediately before `pushKeys`, and asserts `peeked - pushed >= 50`. The sleep starts after the
key is read (after `pushed`) and "a1" appears after it ends, so true elapsed >= 50 ms; poll
lateness only lengthens the measure. The 200 ms pause keeps worker start-up out of the measure,
so a no-op sleep cannot hide behind start-up latency.

## Commands

- 20 runs of `node tests/host/worker.mjs` with 2 x ncpu `perl` busy loops running (plus an
  unrelated 4-thread job already on the machine): 20 pass, 0 fail.
- Mutant: host/worker.js `advance` changed to `(ms) => 0` (reverted after): the test fails
  3 of 3 runs ("took 6 ms", "6 ms", "9 ms"). A first version without the 200 ms pause failed the
  mutant only narrowly (43 ms under load), which motivated the pause.
- `make check`: exit 0 (host glue 600 / 630, total 11679 / 15000; LOC unchanged, no counted path touched).
