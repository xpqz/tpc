### TP5 findings (probed)

1. `Inc`/`Dec`: argument must be an ordinal variable. Integer types, Char, Boolean (`Inc(bo)` is accepted), enums and
   subranges are accepted; Real, String, array, pointer (typed and `Pointer`) are 104. `Inc(5)`, `Inc(Red)` are 20,
   `Inc(i + 1)` is 89, `Inc(ParamCount)` is 122. The step must be an integer expression: Real, Char, Boolean, a
   one-character literal are 38; a LongInt or Word step is fine for an Integer variable. `Inc(i, 1, 2)` is 89, `Inc;` is 88.
   Wrap-around is silent (Byte 255 + 1 = 0, ShortInt -128 - 1 = 127, Word 0 - 1 = 65535).
2. `Swap`: result is Word for every integer argument (`Swap(255)` of an Integer is 65280, not -256); LongInt swaps its
   low word; a constant is fine. `Hi`/`Lo` take any integer type and use the low word (`Hi(70000)` is 17, `Lo` 112; a
   ShortInt -1 gives 255 for both). Our `Hi`/`Lo` take `Word`, so `Hi(l)` for a LongInt would be 38 today. Real and String
   arguments are 38, a missing argument list is 88.
3. `Str(v[:w[:d]], s)`: `v` Integer or Real (Char, Boolean, String, enum are 79), `s` a String-typed variable (Char,
   `p^` of Integer, `a[1]` of Integer are 66; a literal is 20), exactly two arguments (87 `","`, 89 `")"`), width integer
   expression (38). A negative width is ignored; width 300 gives a 255-character string; the result is truncated to the
   capacity of `s`. `Str(i:3:1, s)` for an integer is 87 (not 89 as `Write` gives): not tested. `Str(i, t)` on `String[3]`
   keeps the first three characters.
4. `Val(s, v, code)`: `s` a string expression (a Char is accepted; Integer is 67), `v` an Integer-type or Real
   variable (Char, Boolean, enum, pointer, array are 103; literal 20), `code` an `Integer` or `Word` variable (LongInt,
   Byte, ShortInt are 98; literal 20), three arguments (89 for four). `Val(s, i, w)` with a Word code is accepted; not
   tested (see deviations below). On any error the variable is set to 0 and `code` is the 1-based position of the first
   offending character (end of string is length + 1; leading spaces are skipped, trailing ones are an error, `' '` is 2).
   Integer text: optional `+`/`-`, then decimal digits or `$` and hex digits (`-$10` is -16, `$-10` is 2); the value is
   accumulated in LongInt, overflow is reported at the digit that overflows (`2147483648` at 10, `-2147483648` at 11,
   `$100000000` at 10, `$FFFFFFFF` is -1); the result is stored with no range check into the variable's width
   (`99999` into Integer is -31073). Real text: sign, digits, optional `.digits`, optional `E[+-]digits`; `.5` and `1.`
   are accepted; `E5` is 1, `1e` is 3, `1e-` is 4, `1.5e2.5` is 6, `$10` is 1.
5. `ParamStr(n)` accepts a LongInt `n` (38 for a string); `ParamCount` takes no argument list (85 for `(1)`), neither is
   assignable or a statement (122); `ParamStr` without arguments is 88. Programs may redeclare all these names.

### Intended behaviour and cost

Everything that can be Pascal is: `ParamCount`, `ParamStr(n: LongInt)`, `Swap(x: LongInt): Word`, `Hi`/`Lo` widened to
`LongInt`, `StrInt(v, width): String`, `ValLong(s, var code): LongInt`, `ValReal(s, var code): Real`. All are ordinary
System routines; `ParamCount`/`ParamStr`/`Swap`/`Hi`/`Lo` need no checker code (the `builtin` flag already gives
38/67/85/88/89). Estimated Pascal: about 100 lines.

Checker (about 55 lines before sharing, target 35; the lead may prune negatives to reach it), all as rewrites of the
call into an assignment so codegen is unchanged except `Str` of a Real:

- `Inc(x[, n])`, `Dec`: `x := Ord(x) +/- n` with the nodes built directly (no `assignable`, so range checking never
  sees it). `x` through `bad_var_arg` (20, 89, 122), ordinal else 104; `n` through `argument_assignable` as LongInt
  (38). About 20 lines. `x` is evaluated twice (new deviation D17: a function call in the target runs twice).
- `Str(v[:w[:d]], s)`: `write_arg` for the value and format, `types.unary(Op::Abs, ...)` for the 79 test, `s` a
  variable of string type else 66. An integer becomes `s := StrInt(v, w)`; a Real becomes `s := Fmt(...)` typed String,
  which codegen evaluates with `host.fmt_real` into a 512-byte temporary and clamps to 255 (about 10 codegen lines).
  About 20 lines.
- `Val(s, v, code)`: arity, `s` through `argument_assignable`, `v` Integer type or Real (103), `code` an Integer
  variable (98), becomes `v := ValLong(s, code)` or `ValReal(s, code)`. About 18 lines.
- Shared: one target-variable helper (replaces the inline copies in `heap_call` and `edit_string`), one arity helper.

Candidates for pruning if the budget demands (each needs bespoke checker lines): the 103 family (`val_target_*`, 5 files),
98 (`val_code_*`, 2 + the corpus program), 79 for `Str` (3 files), `str_target_*` 66 variants.

Proposed deviation entries (the lead decides): D17 `Inc`/`Dec` evaluate a target with side effects twice; D18
`Val(s, i, w)` with a Word code is rejected (26); `ParamStr(0)` is `''`, `ParamCount` is 0.

### Changes

- `runtime/system.pas` (+138): `Lo`/`Hi` take `LongInt`, `Swap`, `ParamCount`, `ParamStr(n: LongInt)`,
  `StrInt(v, w, max)` (digits by `mod`/`div` 10 so -2147483648 works; the width is cut to `max`, the capacity of the
  target), `ValLong` (LongInt accumulation, `$` hex, overflow reported at the overflowing digit, 0 on error),
  `ValReal` (mantissa as a Real, one multiplication or division by 10^k).
- `compiler/src/check.rs`: `Inc Dec Str Val` predeclared (26..29), `convert` rewrites the call to `target := value`
  (`Ord(x) +/- n`, `StrInt(v, w, max)` or a `Fmt` node typed String for a Real, `ValLong`/`ValReal`); `variable`
  (TP's var-argument error, shared with `heap_call` and `edit_string`, which got shorter); helpers `STRINT VALLONG VALREAL`.
- `compiler/src/types.rs`: `convert` holds the type rules (104 ordinal, 66 string target, 79 numeric value, 103 Val target).
- `compiler/src/ast.rs`: `Ast::typed`.
- `compiler/src/codegen.rs`: `str()` evaluates a Real `Fmt` through `fmt_real` into a 512-byte temporary (length clamped
  to 255). The module support is now decided by what the live bodies call (`FMT`, `DIV` bits, `gen` repeats `pass` until
  stable) instead of by any Real node in the arena: `ValReal` lives in System, and hello-world and integer programs
  must not import `fmt_real` or define `RDIV`. `fmt_real` and `RDIV` have independent index shifts (`Layout::fmt`, `div`).
- `tests/lang/PENDING`, `tests/neg/PENDING`: the 12 + 6 targets removed.
