# #79 IDE Files

Branch: 79-ide-files (worktree `worktrees/79-ide-files`).

## Stage 1: RED

### Interface the tests fix (unit `Files`, `ide/files.pas`)

`uses Crt, Buffer, View` inside. Names the tests use:

- `const DefaultName = 'NONAME.PAS'`; `function CurrentName: string`; `function IsModified: Boolean`.
- `procedure ResetFiles`: the text in the Buffer counts as unmodified and unnamed (also run by
  the unit's initialisation).
- `procedure NewFile`, `procedure OpenFile` (asks for the name itself), `function SaveFile: Boolean`
  (True when written), `function SaveIfModified: Boolean` (True when the caller may go on: the
  text is unmodified, or the user answered Y and the save worked, or answered N; False on Esc,
  on a cancelled or failed save). The IDE's Quit will call `SaveIfModified` too.

Behaviour fixed by the tests (to be recorded by the lead):

- "Modified" is not in the Buffer. The draft keeps a fingerprint (polynomial hash mod 1000003)
  of the text at the last load or save and compares it; a change counter in Buffer would be exact
  and shorter (Buffer change needed: a `Modified` flag or counter cleared by `Load`/`Save`); the
  tests do not depend on which, except that they never edit a text back to its saved state.
- Typed names are upper-cased and get `.PAS` when they contain no `.` (`good` opens `GOOD.PAS`,
  `notes.txt` stays `NOTES.TXT`). Prompts are on the status line: `Open file: `, `Save file as: `,
  Enter accepts, Esc cancels, an empty name cancels, Backspace edits, extended keys and control
  codes are ignored, 40 characters at most (the find prompt's editor, copied: `Keys.ReadPromptLine`
  is private; the lead may want it exported from Keys or moved to View).
- The question `Save changes to NAME? (Y/N)` (status line): Y/y saves (asking for a name when
  unnamed) and goes on only if the save worked, N/n discards, Esc cancels, every other key and
  extended key is ignored.
- Open: name first, then the question if the text is modified, then the load. The name of a
  missing file therefore still asks the question first. File missing or path missing: message
  `File not found`, text and name unchanged. Too large (more than 65521 characters with the
  line breaks): message `File too large`, the Buffer is empty and the name is reset to
  NONAME.PAS (keeping the old name would let a Save overwrite the old file with nothing); exactly
  65521 characters loads. Any other IO error: `Cannot read file`. A successful open has no message
  and puts the cursor at the top.
- Save: to the current name; unnamed asks for a name. Success: message `Saved NAME`, name adopted,
  text unmodified. Failure (a path that does not exist): `Cannot write file`, name and
  modified state unchanged. Save always writes, also when unmodified. Load adds a final line
  break to a text without one, so saving it back adds the break.
- New: asks the question when modified, clears the Buffer, name back to NONAME.PAS.
- Not done by Files (needs other units): hiding the Keys block after New/Open (the marks would
  point into replaced text; Main should call `ResetKeys`, or Keys should export a
  `HideBlock`), and `Save As`/F10 menu wiring.

### Tests

77 programs, `tests/lang/ide_files_*` (56, exit 0) and `tests/halt/ide_files_status_*` (21, exit 255
by design, see below). Each has `.pas`, `.keys`, `.dirs` (`ide`, `tests/ide/files_harness`,
`tests/ide/files_fixtures`) and `.out`. Shared test code (not counted): `tests/ide/files_harness/FHARNESS.PAS`
(unit `FHarness`: `Start(prefill)`, `EditLoop` = the main loop as Main will write it: F2 `SaveFile`,
F3 `OpenFile`, Alt-F `NewFile`, Alt-X `SaveIfModified`; `Report(names)`), and fixtures
`tests/ide/files_fixtures/` (`GOOD.TXT`, `OTHER.TXT`, `BLANKS.TXT`, `TABS.TXT`, `EMPTY.TXT`, all
CRLF byte for byte; `.PAS` fixtures are avoided because `tools/tp5.sh` adds a CR to them, so TP
and the runner would see different bytes). `BIG.TXT` (65521 and 65522 characters, 80,000 bytes)
is in the directories of the tests that use it.

- `lang/..._*` (A tests): the script ends with Alt-X and the program calls `Report`, which puts above
  the text `name=... modified|unmodified chars=N` and every file named, read back with
  `ReadLn` as `|line|` rows (`== NAME missing` when absent), then `-- text --`. A text above 600
  characters is dropped from the screen (a paint of 64 KB takes a long time under TP).
  Open (23 programs): loads and names, case, `.PAS` added (via a file saved before), other
  extension, missing file, missing path, missing after a good open, Esc, empty name, Backspace,
  extended keys and `^A` in the prompt, empty file, blank lines and trailing blanks, tabs, two
  opens in a row, unmodified does not ask, modified asks (N, Esc, ignored keys, Y with a name,
  Y unnamed then name, Y unnamed then Esc), missing name while modified, exactly 65521,
  65522 and 80,000 characters (the last two drop the name and show GOOD.TXT unharmed).
  Save (17): unnamed asks, `.PAS` added, typed extension upper-cased, current name does not ask,
  Esc and empty name, Backspace, missing directory, empty text, blank lines, repeated save, replaces
  an existing file, marks unmodified, failure keeps modified, round trip, open then save (tabs,
  and the added final break). New (9) and Quit (6): every answer, Esc, unnamed with name prompt
  and its Esc, capitals, `New` twice, new then save under another name, quit after save.
- `halt/ide_files_status_*` (B tests, 21): the script stops inside the last `ReadKey` so the dump
  shows the status line (exit 255 in the dump; `check_halt` takes the code from it). They check
  the exact text of every prompt (`Open file: go`, empty, at the 40-character cut, `Save file as: ou`,
  the name prompt inside the question), question (named, unnamed, kept after other keys, gone after
  N and Esc), `File not found` for a missing file and path, `File too large`, `Saved GOOD.TXT`,
  `Saved OUT.PAS`, `Cannot write file`, no message after a cancelled or good open, the message
  gone after the next key, and the exact-maximum load (a screen of `x` and no message).

Negative tests: the unit adds no language construct; the error paths (missing file/path, too
large, write failure, cancelled questions) are the negative tests above.

### How the goldens were made

`.out` files come from `tools/tp5.sh` (real TP 5.0) compiling a **draft** `ide/files.pas`
(183 counted lines; kept at `tmp/files_draft.pas`, not committed) with FHARNESS. Test bugs found
while making them, all fixed: `Reset` resolves to `View.Reset` (the harness uses `System.Reset`);
`tools/tp5.sh` gives `.PAS` fixtures a second CR (fixtures renamed `.TXT`); `Ctrl-End` is no key
of Keys (script changed); Report destroyed the text it should have shown (text now kept);
a script that ended with an open question blocked (exit 255) and the halt group was split off.
With the draft in `ide/`, `cargo test --test lang`: 21 passed (all 77 programs byte-identical
from this compiler through `tests/run.mjs`, including the failing `NODIR\X.PAS` save and the
65521-character load); I read the dumps against the intent above.
