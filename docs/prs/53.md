### Measured on TP 5.0 (all with `tools/tp5.sh`, probes in git-ignored `tmp/pr`)

- Include: allowed anywhere in a declaration part, also inside a record type, a routine heading,
  a constant expression and before `program`. Error 118 from `begin` to the token after the
  matching `end`: right after `begin`, in a `case`, between the final `end` and its `;`, and in a
  unit's initialisation part. After the `;` it is allowed. An include file that ends inside a
  statement part is 10 (last line of the include); one that ends inside a comment is 10 too.
- Name: ends at the first blank (`{$I F.INC and more}`), no dot means `.PAS` (`{$I PIECE}` with
  only `PIECE.INC` is 15), `{$I}` is 15, case insensitive. Nesting: 14 includes deep work, the
  15th is `9` reported at the directive's line in the 14th file; a file including itself is 9.
  The same include twice is fine (duplicate identifiers aside). No trailing newline is fine.
- Conditionals: `IFDEF`/`IFNDEF`/`ELSE`/`ENDIF`/`DEFINE`/`UNDEF`, names not case sensitive, text
  after the symbol is ignored (also after `ELSE` and `ENDIF`), no symbol or a non-identifier
  (`1X`) is 2, `ENDIF`/`ELSE` with nothing open is 128, also an `ENDIF`/`ELSE` in an include for
  a conditional of the includer (128 in the include). A second `ELSE` toggles back. An `IF`
  open at the end of its file is 129 on the file's last line; this is also how a `{` never
  closed in skipped text ends (to end of file, 129). An `IF` still open when the active text
  reaches the final `end.` is accepted, as is `ENDIF` after it; text after it is not read.
- Names like `IFDEFX`, `ENDIFS`, `DEFINED`, `ELSEX` are 17. `IFOPT` is accepted by TP (not in
  scope; stays 17 here).
- Skipped text: only strings (to end of line, never an error), comments and conditional
  directives are recognised. A string or comment hides a directive; `end.`, invalid characters
  and numbers, other directives (even `{$Z}`) and `{$I MISSING}` are ignored. Skipped lines
  count for line numbers.
- Predefined: VER50, MSDOS, CPU86, CPU87 (the oracle machine has a coprocessor; the compiler
  defines it always, deviation to record). Not defined: VER40, VER55, VER60, CPU386, WINDOWS,
  DPMI, FPC.
- `{$R+}` in an include stays in force after it (runtime error 201 in the including file).

### Intended behaviour and design (for the lead)

- New `compiler/src/directives.rs` between lexing and parsing (Units/driver component, no
  checker lines): `expand(file, text, files, symbols) -> Result<Vec<Tok>, Diag>` returns the
  tokens of one source file with includes spliced in and skipped text removed. It owns the
  conditional stack, the symbol set (local to the source file; an include shares its includer's
  set), the include depth (14) and the statement-part tracking. `units.rs` calls it instead of
  `lex` in `parse_file`; System goes through it too with an empty file table.
- `lex.rs` becomes an incremental `Lexer` (`next` and a lenient `next_skipping` that recognises
  only strings, comments and newlines and returns directives), so skipped text is "still
  lexed" exactly as TP does. About +30 lexer lines.
- Directive words: `I` followed by blank (or the end) is an include, `I+`/`I-` stay switches
  (200 until #54); `IFDEF IFNDEF ELSE ENDIF DEFINE UNDEF` are matched as whole words.
  Switches (`R`, `F`) and the 17/200 errors move from `parse.rs::drop_directives` into the same
  module, which removes that pass from the parser.
- Statement-part tracking (for 118): count `begin`/`case` up and `end` down from the first
  `begin`; `record ... end` outside statement parts; the state ends after the token that
  follows the final `end`. An include whose tokens end inside a statement part is 10.
- Tokens carry `file` and the `{$R}` state in force; the parser stamps each new node from the
  last token it consumed (`Ast::file`, plus a `range_checks` bit on `Node`). This replaces
  `Ast::range: Vec<RangeSwitch>` and `codegen.rs::range_checking_at`'s position search, which
  cannot order a switch inside an include against nodes of the including file (positions of
  different files are not comparable). Needed for the measured rule that `{$R+}` in an include
  stays on after it. Diagnostics of the parser take their file from the token.
- CLI `read_sources` registers `*.INC` files as well as `*.PAS` (wasm `add_file` takes any
  name); `diag.rs` gains code 9, 118, 128, 129 and their messages.
- Deviation to record: CPU87 is always defined.

### Open questions for the lead

1. The `{$R}` redesign above touches `ast.rs`, `parse.rs`, `codegen.rs` (net lines about zero).
   If you prefer not to, the alternative is to record a deviation (`{$R}` inside an include
   applies only to the include's own nodes); then the rt fixture and
   `range_switch_off_in_an_include_stays_off_after_it` must go. I recommend the redesign.
2. `IFOPT` is out of scope (17 as today); TP accepts it.
3. Fixtures use `.INC`/`.PAS` names; the CLI registers only those two extensions, so an include
   named `X.TXT` is 15 on the CLI (no such test).
