# #51 Typed constants

Branch: `51-typed-constants`

## Stage 1: RED

### Intended behaviour

`const X: T = value;` declares a variable of type `T` in static storage with an initial
value. It is mutable, and inside a routine it is still static (one copy shared by all calls,
recursion included). TP 5.0 facts measured with `tools/tp5.sh` and pinned by the tests:

- Initialisers are constant expressions (existing folding). Scalars, Real (`2` is accepted for a
  Real), strings (cut silently to the capacity), sets of constants, `nil`.
- A scalar may be parenthesised: `(4)`, `(1 + 2) * 3` (the parser must try a list first and
  fall back to an expression).
- Arrays: nested parenthesised lists, one level per dimension. Too few elements: error 87 at the
  closing `)`; too many: 89 at the first extra element. A character array takes a string of
  exactly its length (error 100 otherwise) or a list of characters.
- Records: `(f: v; g: w)`: the fields must be a prefix of the declaration order. A skipped,
  repeated or reordered field is 101, an unknown field or a plain list for a record is 44, a
  prefix is accepted (remaining fields are not initialised; this compiler zeroes them).
- A procedural type is error 99 at the declaration.
- Out-of-range value 76; type mismatch 26; a variable in the initialiser 133.
- Reachability (decision 14): each constant is one data segment, emitted only when a live body
  names it.

Measured TP codes this plan does not test or implement: `n: string[5] = 42` is 102 (this
compiler would say 26). For a list with too many elements TP reports the line of the comma
before the first extra element (this compiler: the element), differing only when the element
starts a new line; the tests keep to single lines. Both are deviations to record at GREEN.

### Design assumptions (for the lead)

- Parser: `name: type = initialiser;`; new AST kinds `TypedConst(name, type name, init)`,
  `ArrayInit(items)` and `RecordInit(items)` (both stamped at the closing parenthesis),
  `FieldInit(name, value)`.
- The checker only validates and resolves the leaves (existing `expr`/`assignable`) and
  allocates the static address; it records `(address, type, init)` in `Info`. The byte image
  (strings padded to capacity, sets as 32 bytes, Reals as f64, records by field offset) is
  built in codegen, only for reachable constants (`Layout` marks the constant when `base` meets
  its address), so layout lives with the other static-data code and the checker stays small.

### How each fails today

All 11 tests fail because the parser stops at the `:` of the declaration: `Error 90: "="
expected` (90) at the colon, instead of the expected result. The corpus-list test fails because
the 25 programs are still in `PENDING`. No test is empty-versus-empty (lang outputs are asserted
non-empty; image tests count exactly one occurrence).
