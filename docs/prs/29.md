## Method

Every `.out` and `.err` was produced by `tools/tp5.sh` (real TP 5.0) on the committed `.pas`;
nothing is hand-written, fpc was not used. Probes lived in `tmp/p29/` (git-ignored).

TP5 findings that shape the design (all probed):

- A nested routine may assign the result of any enclosing function (`Outer := 7` inside a
  nested procedure compiles; the assignment lands in the running activation, last write wins).
  A sibling's function name is still 122. So the function result must be a capturable variable.
- A `for` control variable must be a variable of the current routine or a global: a local or
  `var` parameter of an enclosing routine gives 97 (a global in a routine is accepted).
- A nested routine may reuse the name of its enclosing routine (inside the enclosing routine the
  name then means the nested one); a nested routine named like a local or parameter of the same
  routine is 4.
- Names of nested routines and their locals are not visible outside (3); a nested routine is
  visible only after its declaration (3), also to deeper nested routines.
- An undefined `forward` in a nested scope is 59, reported on that routine's `begin`.

## Intended behaviour (design the tests assume)

- Symbols carry the lexical `depth` of their routine (main 0, top-level routines 1, nested 2...);
  `Routine` carries `depth` and whether it has nested routines.
- A reference to a `Local` or `Ref` symbol from a deeper routine sets `taken` (the `captured`
  flag of plan §4.3 is the same flag): `Local` moves to the frame as in #28; a captured `Ref`
  (var parameter) becomes `FrameRef`: its address is copied into a 4-byte frame slot and
  reads/writes load that address first. The function result becomes a real (unnamed) symbol so
  that nested routines can capture it; the epilogue reads it from the frame when it lives there.
- A routine with an enclosing routine (depth > 1) takes the static link as WASM parameter 0
  (before the declared parameters); its frame, when it has one, reserves offset 0..4 and the
  prologue stores the link there. Frame offsets start at 4 for such routines, 0 otherwise, so
  the #28 frame sizes are unchanged. A routine has a frame if it has taken variables or nested
  routines (a routine with nested routines and no variables has frame size 0: `fp = sp`).
- Access at depth difference d > 0: start from the link parameter, load word 0 d-1 times; offset
  goes in the memarg. A call to a routine of depth k+1 passes the frame pointer of the caller's
  ancestor at depth k: the caller's own `fp` when it is that routine, else its link walked.
- `for` rejects a `Local` or `Ref` of an enclosing routine with 97 (as it does for `Ref` today).
- Errors: routine declarations inside routines are scoped like variables (4 for clashes, 3 for
  out-of-scope use); an undefined `forward` is checked at the end of each declaration part (59 at
  the routine's `begin`).
- Expected LOC: checker about +60, codegen about +50, types +10.

## Open points for the lead

1. Assignment to an enclosing function's result from a nested routine (TP5 accepts) needs the
   result as a capturable symbol; the tests expect it supported, not 200. Say if it should be cut
   to 200 instead (then `nested_enclosing_function_result_assigned` and the ACCEPTED entry go).
2. `docs/abi.md` §4 says frame offset 0 holds the static link. This design reserves it only for
   routines that have a parent, to keep #28 sizes; the tests pin it.
