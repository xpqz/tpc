Intended behaviour: `uses Crt` finds the embedded `runtime/crt.pas` (never a user `CRT.PAS`); its initialisation replaces
System's console writer and console line reader, so plain Write/WriteLn/ReadLn use the window, cursor and TextAttr; programs
without Crt compile to the same imports (and, checked in GREEN, the same bytes).

### Finding that shaped the design

TP's Write holds the text in the file buffer until the end of the statement (`WriteLn('[', WhereX, ']')` shows the cursor
before the `[`; corpus `crt_wherex_wherey_track_writes`). Hence the buffer in System and the `TextFlush` call.
`crt_unit.rs` pins the clock and imports as described in RED.

### Byte identity for programs without Crt: not achievable, quantified

Compared the compiled non-Crt programs of `tests/lang` and `tests/abi` (542 compile with both) between `7af6abd` and this
branch: 0 identical, 542 differ; 70 are rejected by both. Every module now contains the console hooks: a table with a trap stub,
the extra function types, `call_indirect` in `ConsoleWrite`, the 128-byte buffer path, the `TextFlush` calls. Hello-world is
676 -> 868 bytes (limit 2048, `docs/size.md`). A hook that is a runtime-decided procedural value cannot be removed by the
dead-code elimination, so identity would need a compile-time choice of console (compiler support), which the brief excludes.
