## Stage 2: GREEN

### Changes

- `compiler/src/check.rs`: `call_statement` no longer rejects a callee that is not a plain
  name with 113. It hands it to the new `designator_call_statement`, which checks the
  designator as an expression (the path of #52's `designator_call`), requires a procedure
  type (a function type or a non-procedural type is 91, as TP, and as the plain-variable
  case already is), checks the arguments with `arguments` (89/88/26 come from there) and
  rewrites the call to `Indirect`. Codegen and the parser already handled `Indirect` of a
  designator from expression position; no change there.

- A bare name that is a field of an enclosing `with` record (`with m do show(1)`, `first;`) takes
  the same path: the field hides a routine of that name, as in TP (the corpus program prints
  `twice 2`, not the global `Show`). Expression position (`call_expr`) still resolves such a
  name to the global routine first; not touched here.

Design decision: the former 113 for `a.b;` was a guess; TP gives 91 for a designator that is no
procedure, so one rule covers all non-procedural designators.
