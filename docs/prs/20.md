### Oracle findings that differ from the issue text (tests follow TP5)

- 37 "END expected" is not reachable in this grammar: a statement followed by anything other
  than `;` or `end` is 85 (`begin`, `until`, `.`, EOF-less cases alike). No test expects 37.
- Error 10 is reported on the last line of the file (the number of lines), not the line
  after the final newline; an empty file (source `\n`) is line 1.
- `;` then `.` inside the body is 113; `end` then `end.` is 94 at the second `end`.
- Errors are reported at the lookahead token (e.g. missing `)` is on the line of the next
  token), per lead.
- Not tested, left to later slices: `program P(Input, Output);` (TP accepts), error 11
  (line over 127 characters; not in the diag table), `^)` and a lone `?`.

- `compiler/src/parse.rs`: `parse(tokens) -> (Ast, root)`. Helpers `err` (error at the

- `compiler/src/lex.rs`: lexing stops after `END` `.`, as TP ignores the rest of the file
  (an unterminated string after the final `.` must not fail).
- Control characters `^X` are string literals of one byte for now (TP types them as Char).

### Design decisions

- Statement `Ident [ (args) ]` is parsed as `Call` and rewritten in place to `Write` by the
  checker (contract: resolution in place); expression identifiers are `Name`, which the
  checker rejects with 3 until symbols exist.
- `Types` is created by `check` and returned so codegen can take it once it needs sizes.
- End-of-file mapping lives in the driver so parser and lexer report positions unchanged.
