# #73 Firefox BiDi start-up is not robust

Branch: 73-firefox-bidi-start-up-is-not-robust

## Problem
`firefoxBackend` polled `ws://localhost:PORT/session` every 20 ms, opening a new WebSocket per
probe, with a 15 s deadline. On a slow cold start (fresh profile) the deadline expired
("timed out waiting for Firefox's BiDi socket"). Chrome and the dev server used the same
poll-with-deadline pattern.

## Change (tests/host/browser/chrome.mjs only)
- New `announced(child, stream, pattern, what)`: resolves when the child prints its readiness
  line, rejects at once if the child exits first (with its output), plus a 90 s hang guard.
- Firefox: waits for `WebDriver BiDi listening on ws://HOST:PORT` on stderr, then connects once.
- Chrome: waits for `DevTools listening on ws://HOST:PORT/...` on stderr instead of polling the
  `DevToolsActivePort` file.
- Dev server: waits for its `http://localhost` line on stdout instead of fetch polling.
- `until` default deadline raised 15 s to 90 s and documented as a hang guard only
  (it still polls in-page conditions, which have no event to wait on).
