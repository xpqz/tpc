# #92 Heap exhaustion must end in runtime error 203

Branch: the worktree branch of issue 92. No RED stop (pre-approved).

## Cause

The premise of the issue is wrong: neither `entry/0030.pas` nor `pointers/0013.pas` allocates
in a loop that is unbounded. Heap and linear memory are not involved.

- `entry/0030.pas`: `getnbr2` loops `repeat Write(msg); ReadLn(s); Val(s, x, i) until i = 0 ...`.
  With an empty stdin `ReadLn` returns an empty string at the end of the input, `Val` fails,
  and the loop never ends. It writes a prompt on every turn.
- `pointers/0013.pas`: the `Read(Achar)` menu loop gets no character at the end of the input,
  takes the `else` branch and writes "Invalid option" on every turn, forever.
- TP also loops on both (swag.md: TP times out), so there is no TP runtime error to match.

What grew was node: `tests/run.mjs` keeps every byte of stdout in an array until the program
ends. Evidence (empty stdin, 15 s): `/usr/bin/time -l timeout 15 node tests/run.mjs --in empty.in
a.wasm` reports a maximum resident set size of 4224237568 bytes. `grep -rn "memory.grow"
compiler/src host runtime` finds nothing: the wasm memory is fixed (decision 18). The real
heap path is already covered by `tests/rt/heap_overflow_*` (203 on exhaustion), which pass.

## Fix

`tests/run.mjs`: the runner counts the stdout bytes it collects and, past `TP5_OUTPUT_LIMIT`
(default 64 MiB), throws a `RunnerError` "output limit of N bytes exceeded" (exit 2, the output
so far on stdout). `tools/swag.py`: that error is classified as `timeout`, as TP's run is.
No change to runtime, compiler or host, so no LOC change.

## Test

`compiler/tests/runner_output_limit.rs`:
- `endless_output_stops_at_the_limit`: the `ReadLn`/`Val` retry loop with empty stdin and a
  limit of 100000 exits 2 with "output limit" on stderr and between 1 and 100064 bytes on
  stdout. Before the fix it ran until node was killed (exit status -1 after 24 s, ~4 GB).
- `a_program_within_the_limit_is_unaffected`: hello world under a 100-byte limit prints
  `hello` and exits 0.

No tests/rt test: TP does not end on such a program, so there is no expected output.

## Commands

- `cargo test --test runner_output_limit` before the fix: 1 passed, 1 failed (-1, 24 s);
  after: 2 passed, 0.08 s.
- Both SWAG programs with empty stdin now end in about 3 s with the limit error.
- `make check`: see the report (run last, exit status gated).
