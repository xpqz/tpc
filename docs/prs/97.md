# #97 IDE title bar loses the file name while a menu is open

Branch: 97-ide-title-bar-loses-the-file-name-while-a-menu-is-open.

## RED

New halt test `tests/halt/ide_main_title_stays_while_a_menu_is_open` (Main + Files with a
named file: F2, type `out`, Enter, then Alt-F; the screen is dumped with the pull-down open).
Before the fix `tools/tp5.sh` printed row 1 as ` File  Run  Compile  Options` with no
`OUT.PAS` (`grep -c OUT.PAS` gave 0): the bug. After the fix row 1 ends with `OUT.PAS`
(count 1). The golden was written by `tools/tp5.sh` after the fix. It is a halt test because
the program blocks on a read after the last key (exit 255). IDE LOC before: 1381 / 2500.

## Fix

The file name is part of the bar. `Menu.WriteBar` (used by `DrawBar` and `Show`) now also
writes ` NAME ` at the right end of row 1 via `Files.CurrentName`; Menu uses Files (no cycle:
Files uses only Crt, Buffer, View). `Main.DrawTitle`, its constant and its call are removed.

## Goldens

Menu tests drive Menu directly with an unnamed file, so their row 1 now shows `NONAME.PAS`
as Main always did. 40 goldens in `tests/lang` and 1 in `tests/halt` (`ide_main_menu_run_item`)
were regenerated with `tools/tp5.sh`; the diff touches only row 1 of each (checked with
`git diff -U0`).

## Commands

- `make check` after the fix and regeneration: exit 0.
- IDE LOC after: 1377 / 2500 (delta -4). Total 10840 / 15000.
