### How they fail today

All fail on compile errors from the current parser (113 at the first `if`/`while`/`repeat`/
`for`) except the division cases: Integer min `div` -1 prints 32768, `mod` prints 0, the
nested one prints -32768 (all exit 0), LongInt min `div` -1 traps in WASM, and
`variable_div_constant_zero` is rejected with 62 at compile time. Several `ERR` cases
(`else_without_if`, `then_without_if`, `until_without_repeat`, `do_without_loop`) already
pass; they pin existing behaviour.

### Oracle findings

- `{$B-}` is the default: `(i <> 0) and (10 div i > 1)` with i = 0 does not fail; `or` likewise.
- `if x then else y` and `... else;` are valid (empty statements). An empty statement is
  allowed before `else` only in a then-branch, before `until` only inside `repeat`, before
  `end` only inside a compound: `repeat x; end` is 113 and `begin else` is 113.
- `repeat x end` (no `;`) is 85 at the `end`; `if c then a; else b` is 113 at the `else`.
- A `for` variable that is a constant or missing is 20; a missing `:=` is 91; bound type
  errors are 26; constant bounds outside the variable's range are 76.
- Division: LongInt -2147483648 div -1 = -2147483648 and mod -1 = 0; Integer -32768 div/mod -1 is
  Runtime error 200; ShortInt -128 div -1 = 128 (operands widen to Integer).
- `i div 0` with a variable `i` compiles and fails at run time (200); only an all-constant
  expression is 62.

### Intended behaviour

Statements `if/then/else`, `while`, `repeat/until`, `for` to/downto in parser, checker and
codegen; Boolean `and`/`or` short-circuit in codegen; `for` evaluates start then end once into
a hidden local and tests for equality before incrementing so limits do not wrap; division
helper handles divisor -1 (LongInt: negate / 0; Integer: error 200 for -32768) and zero.
Empty statements per the context rule above. At GREEN: remove the passing programs from
PENDING.
