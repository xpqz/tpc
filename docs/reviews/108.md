# Review #108: Packaging and in-editor tests

## Verdict: approve (review 1)

`make vscode` builds a self-contained extension and a VSIX without vsce: manifest from
package.json, the 9 host files it imports, and the bundled tp5c.wasm, which locate.mjs finds
first. Host code is imported through one module (vscode/src/host.mjs) whose paths the package
build rewrites, so the repo version still runs as a development extension. `make test-vscode`
(opt-in) runs 7 tests against the real VS Code API, in a separate profile and extensions
directory. They pass against the repo extension and against the packaged one; the error
numbers and lines come from the oracle. The VSIX installs into a throwaway extensions
directory. Activate returns `{ runs }` for the tests, documented. The test profile under
os.tmpdir() instead of tmp/ is approved: VS Code's socket path limit forbids the worktree
path.

The first `make check` hung in a vscode test with no CPU use. The lead converted the last
asynchronous WebAssembly compile in the vscode tests (ffi_message) to the synchronous form,
the known Node 23 hang. The gate below ran after that.
