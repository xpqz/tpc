# Review #95: Size pass

## Verdict: red-approved (RED review)

The measurement is clear, and the tool and the size tests are useful. The 7 failures are the
stated waste. The 4 guards and the new corpus programs (from the oracle) protect behaviour.

1. KB means 1,000 bytes: the compiler target is 250,000 B stripped. Say so in docs/size.md.
   At 254,558 B the compiler is over it, so it gets a fix, not a reinterpretation.
2. Approved: `strip = true` in the release profile. Confirm by rebuilding that all three
   custom sections are gone. The `make wasm` check stays.
3. Approved: build write_integer and quotient, and import rterror, only when the program
   needs them. Keep mark/emit the single place that decides, in the existing style. Tighten
   the hello-world bound to the measured size plus about 5%.
4. Approved: register WASM types only for procedural types that a call_indirect (or a
   procedural value) uses. Test it with a program that declares an unused procedural type.
5. Approved: strip comments and blank lines from the embedded runtime sources in build.rs
   (counted). Constraints:
   - Directives are comments that are not comments: keep every `{$...}` and `(*$...*)`.
   - Never strip inside a string literal (`'{'`, `''''`).
   - Handle both `{ }` and `(* *)`.
   - Keep the line count unchanged: replace each comment's text, never its newlines. A
     runtime error's line in a unit and every diagnostic stay the same, even though embedded
     units report line 0 today.
   - Plain, readable code with a comment that states those rules.
   Tests in compiler/tests/: the stripper on the cases above (brace in a string, nested
   kinds `{ (* }`, a directive, a comment spanning lines keeps its newlines), and that the
   embedded System source in the binary is smaller than the file. Also show that the whole
   corpus is unchanged. Report the bytes saved.
6. Not approved: splitting data segments at zero runs. The IDE is 21.6 KB against 120 KB,
   so it is not worth 10 lines.
7. GREEN: one commit per fix with its size before and after. Run `make check` (in the
   background if it is long), and add a phase-8 size-pass row to docs/size.md.

## Verdict: changes (GREEN review 1)

The results are good: compiler 234,407 B (target 250,000), hello-world 691 B, and no custom
sections. build.rs is plain and states its rules. DCE now marks rterror through helper_index
wherever generated code raises an error (stack check, Sqrt, division), so a program that
needs it still gets it. Three small points:

1. hello_world_does_not_import_rterror was wrong at RED, and my approval of it was wrong too:
   WriteLn is followed by CheckIo, which can raise an I/O error, so every program that writes
   reaches rterror legitimately. Changing it is approved. Assert instead that the empty
   program does not import rterror, and that a program which divides an Integer does. Record
   the justification in docs/prs/95.md.
2. In register_procedural_types, `if let (true, Type::Proc { .. }) = (called[i], t)` is a
   tuple-pattern trick. Write it as `if !called[i] { continue; }` followed by the plain
   `if let`.
3. In Indexes::new, the `number_if` closure that mutates `next` is harder to follow than it
   needs to be. Prefer a small plain helper, or straight-line code: `let mut next = ...;`
   followed by one `if` per built-in. Pick whichever reads better, and keep the comment
   saying the numbering order.
Then `make check` exit 0 (in the background if it is long), commit, and report.
