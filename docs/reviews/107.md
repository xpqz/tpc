The tests are strong. Every one of the 51 tests/lang/crt_* programs runs in the worker, and
its final grid is compared with the oracle's screen dump. So is the ANSI stream replayed in a
strict emulator. The key table is checked against host/keys.js for 278 sequences, and the
flood test pins the message bound. The failures are the stated ones.

1. The two edits to existing tests (the Crt message assertion dropped, and "uses Crt" now
   expecting the alternate screen) are approved: the behaviour they pinned is the one this
   issue replaces.
2. The alternate screen at the end: keep the program's final picture on the alternate screen
   until a key is pressed, as TP's user screen does, so a program that draws and exits can be
   seen. Then leave the alternate screen and show the end text and the close prompt on the
   normal screen as in #106. Add a test for it.
3. The design choices in the PR doc are approved: blink as a bright background, a full SGR on
   each colour change, the frame order, the notice when the window is small.
4. At GREEN, run the crt_run and output_flood files three times in a row (timing), then
   `make check`.

The output ring replaces the approved batch, and the change is approved. The worker runs the
program in one synchronous call and so cannot run a timer; a ring the extension drains every
20 ms bounds the messages and lets a fast writer wait instead of filling memory. The module
explains this in its comment. The test edits are approved as corrections of RED mistakes:
F10 is 0,68 (Table C.2); the row count; Uint8Array compared with deepEqual; the line
arithmetic; the fixture directory; the oracle IDE program covered elsewhere; the hold and a
second key to close, from review point 2. The synchronous compile in compiler_service fixes the
Node 23 hang (as decision/issue 93 did for the runner). The frame copy avoids a lost cell.
Counted code unchanged.
